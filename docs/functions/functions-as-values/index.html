Functions as Values

Also known as: first class function higher order function pointer delegate callback rest parameters variadic varargs ...args *args spread any number of arguments

● Beginner5 minBefore this: LambdasSpec 3.4

A function is a value: store it in a variable, or pass it to another function.

In simple terms

A function can be handed around like any other thing: kept in a variable, or given to another function that decides when to use it, like handing a recipe to a friend.

fn(Int, Int) -> Int is the type of a function that takes two Ints and gives one. apply_twice takes such a function as its parameter f and calls it.

Functions in a collection

A function goes in a list or a dict like any value. A dict from names to functions picks what to do by a name, as for commands or a calculator's keys:

  • {"add": add} stores the function add itself, not a call: no brackets after its name.
  • Named functions and lambdas mix, when they take and give the same types. Here the dict is a {String: fn(Int, Int) -> Int}, worked out from its values.
  • steps[0](10, 5) takes the first function from the list and calls it.
  • A dict gives an optional, as the name may be missing, so if let f = ops["mul"] calls it only when it is there.

Functions can sit deeper too, next to records, dicts and lists: see Nested and Mixed Collections.

Functions that can fail

A function type says what its functions can fail with, and what they may use, in the order of a signature: fn(NewOrder) -> Order ! ShopError uses Db. Several capabilities go in parentheses: uses (Net, Db).

  • handle takes any function that can fail. Its error type E is a type parameter, so handle fails with place's own ShopError, and the match on it must cover every case.
  • Calling a function value that can fail is a call that can fail: try, catch or match, as for any other call.
  • A function that can't fail fits any function type, with ! or without.
  • With uses, a function value may use only what its type lists; without it, the type sets no limit. See Pure Functions.

A function that can fail doesn't fit a type without !, since its error would be lost:

A method can take a function that can fail too, call it, and handle its error. Here using gives the connection back whether work succeeds or fails, then passes the error on with fail e:

Any number of values

There are no rest parameters, such as ...args in JavaScript or *args in Python. A function that takes any number of values takes a list, and a call puts them in brackets:

  • An empty list is fine: total([]) is 0.
  • A list you already have passes on as it is. There is no spread operator to learn, such as ...list or *list.
  • The parameter is like any other, so it mixes with named arguments and defaults without extra rules. Rust, Zig and Haskell do the same.
