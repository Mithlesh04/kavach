The Machine

● Intermediate8 minBefore this: Capabilities, Running ProgramsSpec 14.25

std.system says what machine the program runs on: its system, processor, memory, GPUs, drives and devices, and the programs and users on it. The basics are free; what could tell one machine from another needs System, and what is critical needs System.critical.

In simple terms

Before you split a job between workers, you want to know how many workers the machine has. std.system answers that, and more: how much memory there is, which GPUs, how long the machine has been on. The questions that could identify a machine need your permission first.

The most common use: split work across every core the machine has.

  • system.cores() gives logical, how many threads can run at once, and physical, the cores behind them.
  • system.os() gives the system's name and version, and system.arch() the processor's architecture, such as "x86_64".
  • These three need no capability, like the clock: many machines share each answer, so they identify no one.

The rest needs System

Memory, the processor's name, the GPUs, the hostname and the uptime together can tell one machine from another. So a function that reads them says uses System:

  • system.memory() gives total and available in bytes: what a program could still take without the system swapping.
  • system.gpus() lists each GPU, discrete ones first. Each has a kind: Discrete, Integrated, Virtual, Other, or Software for one that draws on the processor. Listing them opens no GPU.
  • system.uptime() is a Duration.
  • kavach audit lists System, and an agent gets it only when a person approves.

Every part of the machine

Drives, volumes, network adapters, displays, the battery, sensors and every device the system knows come as typed records, and need System too. Each call reads the machine again, so a pen drive plugged in shows in the next call. What a system doesn't say is "", 0 or an empty list, never an error:

What is critical needs System.critical

Some things are critical to the machine and the people on it. System.critical.read reads them: the applications installed, the serial numbers and network addresses that name this exact machine, the programs running and the ports they hold. System.critical.write changes the machine for everyone on it.

uses System doesn't cover either. A function writes them by name, kavach audit lists them apart, and an agent gets one only when a person approves:

net.free_port() -> Int ! NetErrorA TCP port nothing listens on now, chosen by the systemNet

  • A change needs the system's own permission too. A program not run as an administrator, or as root, can end only its own user's programs, and can't add or remove users. A change refused fails with SystemError.Denied.
  • SystemError is NotFound(what:), Denied(reason:) or Failed(reason:).
  • A port found free can be taken by another program before yours listens on it. A server that can should listen on port 0 and read the port it got.
  • Tests can't change the machine: a test that calls one of these changes is refused.
