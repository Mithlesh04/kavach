GPU Screens: Drawing for user interfaces

● Intermediate7 minBefore this: GPU Screens

A user interface draws thousands of small shapes a frame. std.gpu clips them to a box, masks them to a rounded shape, smooths their edges, draws into canvases off the screen, and changes part of a texture as a glyph atlas grows.

In simple terms

Think of a scrolled list in an app: the rows must not spill out of their box, the box has round corners, and text must look sharp. These are the tools a UI library builds that on.

These are building blocks for a UI library, not a UI library. A frame keeps a state that every draw after it follows: a clip, a mask and a way of blending. A panel clips to its scrolled box and draws its text only inside its rounded shape:

from spec 14.24.1

Canvases: drawing off the screen

A canvas is a picture off the screen. You draw into it as into a window, then read its pixels back or draw from it as a texture. It opens no window, so it works where there is no screen, given a GPU. Here a 4 × 4 canvas is cleared red and read back:

  • A new canvas is transparent black: all four parts of every pixel are 0.
  • canvas.pixels() gives four bytes a pixel (red, green, blue, opacity), row by row from the top, as the last frame shown left them. It waits for the GPU.
  • A canvas's frame is a Frame like a screen's, with every method below. It doesn't wait for the screen's refresh.
  • It needs Window, as all drawing does, though it opens no window.
Function or methodGives
gpu.canvas(width, height) -> Canvas ! GpuErrorA canvas width × height pixels (1 to 8192 each), every pixel transparent black: all four parts 0
canvas.frame() -> Frame ! GpuErrorThe next picture to draw into it; frame.show() finishes the drawing, which then shows in its pixels and its texture
canvas.pixels() -> [UInt8]Its pixels as its last frame shown left them: four for each pixel (red, green, blue and opacity, in sRGB), row by row from the top. It waits for the GPU
canvas.texture() -> TextureThe canvas as a texture for fragment fns to read, which changes as the canvas is drawn into; nearest: true samples it to the nearest pixel. Only the GPU reads it: sample on the CPU is a panic (a contract), as for a compressed texture
canvas.width, canvas.height: IntIts size in pixels

A draw into a canvas can't read that canvas's own texture: a picture can't be read while it is drawn.

How a frame draws

MethodFrom now on
frame.set_clip(x, y, width, height)Draws change only the pixels inside this rectangle, in pixels from the frame's top left. A rectangle past the frame's edges is cut to them; one of no pixels draws nothing
frame.clear_clip()Draws change any pixel again
frame.set_premultiplied(on)Draws blend their colours as premultiplied: the fragment fn's red, green and blue are already multiplied by its opacity, as a picture of soft edges keeps them. Off at first: a colour is blended by its opacity, as before
frame.set_mask(mask)Draws use the frame's mask: Mask.Off, not at all (at first); Mask.Write, a draw marks the pixels where its fragment fn gives an opacity above 0, and colours none; Mask.Inside, it draws only on marked pixels; Mask.Outside, only on others
frame.clear_mask()Unmarks every pixel. frame.clear unmarks them too

Clipping. set_clip keeps draws inside a rectangle, in pixels from the frame's top left. Here a white square over the whole canvas changes only its left half, until clear_clip:

Masks. For a shape that isn't a rectangle, such as a box with rounded corners, a draw with Mask.Write marks the pixels it covers and colours none. After that, Mask.Inside draws only on marked pixels, and Mask.Outside only on the others. Here the left half is marked, then red is drawn inside and blue outside:

  • A pixel is marked or not: marking it twice marks it once. Masks don't nest.
  • A rectangle is cheaper with set_clip than with a mask.
  • set_clip with a negative number is a panic. A rectangle past the frame's edges is cut to them.
  • A new frame starts with no clip, no mask and plain blending.
  • A pipeline's first draw with a mask or premultiplied blending compiles that form of it. Draw it once while the program loads, so no frame waits for it.

Premultiplied blending. With set_premultiplied(true), a fragment fn's red, green and blue are taken as already multiplied by its opacity, as pictures with soft edges keep them. This avoids dark fringes around text and icons.

Smooth edges

With samples: 4, on gpu.screen or gpu.canvas, each pixel is drawn from 4 samples and blended when shown. A pixel that a triangle's edge crosses is then partly coloured, so the edge looks smooth, not stepped:

  • It costs the GPU about four times the memory for the picture.
  • samples is 1 or 4; any other number is a panic.

Textures for text and pictures

  • One channel. channels: 1 takes one byte a pixel, a quarter of the memory. sample gives the value as red: (value, 0.0, 0.0, 1.0). It is a value, not a colour, as a glyph atlas's coverage is (see Fonts).
  • Nearest pixel. nearest: true samples the pixel under the spot instead of blending the four nearest: for pixel art, and for a glyph atlas drawn at its own size. The textures of one draw are all nearest, or none is.
  • Changing part of a texture. gpu.update(t, x, y, width, height, pixels) changes only that part, on the GPU and in t, so sample on the CPU sees it too.
