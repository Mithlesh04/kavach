GPU Screens

● Intermediate4 minBefore this: WindowsSpec 14.24

std.gpu draws into a window with the GPU: a screen for the window, a frame for each picture, cleared and shown at the screen's rate, with triangles drawn by gpu fns written in Kavach.

In simple terms

A window is a frame on the screen; the GPU is the fast painter that fills it. Each picture is painted on a fresh canvas and then shown, many times a second, which is how games and animations move.

from spec 14.24
  • gpu.screen(win) gives what draws into the window, using the program's GPU.
  • screen.frame() gives the next picture, as big as the window is now. It waits for the screen's next refresh when the last picture isn't shown yet (vsync), so the loop runs at the screen's rate.
  • frame.clear(r, g, b) fills it with one color, each part from 0 to 1, and frame.show() puts it on the screen. A frame never shown is thrown away.
  • Drawing changes the program's own windows, so it needs Window.
  • Where there is no GPU, or the window can't be drawn into, it fails with GpuError.Unavailable(reason). So does a frame of a minimized window; the next frame() tries again. A KTX2 file that can't be read is GpuError.BadTexture(reason).

A private function may leave its uses out, and the compiler works it out. A pub one must say it, so a function that draws for other modules names Window:

Drawing triangles

Triangles are drawn by two kinds of gpu fn: a gpu vertex fn works out where each corner goes on the screen, and a gpu fragment fn gives the color of each pixel inside. gpu.pipeline joins them, and frame.draw draws with it. See Drawing triangles.

  • A draw paints over what the frame already holds, blending by opacity.
  • Without indices:, each three vertices make a triangle. With indices: corners, a [UInt32], each three numbers name a triangle's vertices by their place in the list. So a corner two triangles share is one vertex: a square is four vertices and six indices, not six vertices.
  • An index past the last vertex is a panic, before anything is drawn.
  • A draw without the instances: or shared: value its vertex fn takes is a compile error.
  • A list a GPU map made is drawn from GPU memory, with nothing copied.
  • A pipeline is compiled for the GPU when it is made, or when a screen opens, never in the middle of a frame.

step 1 of 10

While compiling, the compiler checks place and glow, and that glow takes what place gives. It writes both into one WGSL module, a GPU program. Its first line tells the runtime how the buffers are laid out: a corner is 2 Float32s, a dot 3, the shared Camera 1.

A window program: the compiler checked this code, and the site doesn't run it. One frame of the loop is shown; each frame makes its buffers anew and lets the last ones go. Simplified: the GPU's memory also holds buffers for copying, and the GPU may run place once for each index rather than each corner.

    Before anything is drawn, the runtime checks, while running, that each of the 6 indices names one of square's 4 corners. An index of 4 or more would stop the program here with a panic, and nothing would be drawn.
  6. Line 42: frame.draw(dots, square, instances: swarm, shared: Camera(zoom: 1.0), indices: corners)
    Each draw makes new buffers in VRAM and copies them over: the vertices, the instances, the indices and the shared value. Only a list a GPU map left in GPU memory is drawn where it is, with nothing copied. The draw is noted in the frame; the GPU hasn't drawn yet.
  7. Line 43: frame.show()
    show sends the frame's work, the clear and the draw, to the GPU in one go, and asks for the picture to be shown. The CPU goes on to the next round of the loop while the GPU draws.
  8. Line 25: Lit(position: ((c.x + d.x) * cam.zoom, (c.y + d.y) * cam.zoom, 0.0, 1.0), heat: d.heat)
    The GPU runs place on its many small cores, for each corner of each dot: 4 corners × 2 dots. Corner (-0.1, -0.1) of dot 0 lands at (-0.6, -0.1). heat goes on to glow. An overflow here gives a wrong value, not a panic: the GPU can't stop in the middle of a frame.
  9. Line 29: (l.heat, 0.2, 1.0 - l.heat, 1.0)
    The GPU joins the corners into triangles, finds the pixels inside each, and runs glow once for each of them: dot 0's pixels get (0.2, 0.2, 0.8), blue; dot 1's (0.9, 0.2, about 0.1), red. Each lands in the picture.
  10. Line 43: frame.show()
    At the screen's next refresh the picture is shown: Fifo, vsync. Then the loop draws the next frame, 600 in all, with new buffers each time.
