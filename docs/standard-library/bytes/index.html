Bytes

Also known as: bytes byte array buffer binary blob raw data utf-8 encoding as_list of_list read numbers float32 little endian decode

● Intermediate5 minBefore this: StringsSpec 2.13

Bytes holds raw data: a file's contents, an image, a network message. It is stored compactly, one byte per byte.

In simple terms

Underneath, every file, picture and network message is a long row of bytes. Bytes holds that row exactly as it is, without reading it as text, so you can store it, send it, check it for damage, or read the numbers in it.

Checking data

A checksum changes when the data does, even by one letter, so it shows data that was damaged on the way. get gives none past the end, where b[i] would stop the program.

Reading numbers

Data often holds numbers, such as a chunk of a file. b.as_list<T>() reads them all, without going through the bytes one by one. It gives none when the length isn't a whole number of them:

T says how to read the bytes, and how many make one number:

  • The bytes are little-endian, smallest part first. Nearly all files and processors use that order, so data reads the same on every machine.
  • The list is a copy, made in one go, with no work for each number. Changing the list leaves the bytes as they were.

One number at a place

A file format or a network message puts each number at its own place. b.read<T>(at) reads the one whose bytes start at at, and Bytes.of<T>(n) gives a number's bytes, to build a message with +:

  • The bytes are little-endian unless big_endian: true, the order network protocols and some file formats use.
  • A read whose bytes don't all fit gives none, as b.get(i) does past the end. So does a negative at.
  • T is a number of fixed size, as for as_list:

A whole list as bytes

Bytes.of_list<T>(xs) is the reverse of as_list: every number in the list as bytes, in order, to write to a file or send. It copies them all at once, instead of joining a Bytes.of for each number:

  • Each number's bytes are as Bytes.of<T> gives them, little-endian unless big_endian: true.
  • as_list<T> reads them back, so the round trip gives the same list.
  • T is a number of fixed size, and must be written:

Text from part of the bytes

A line read from a file or a network often holds words at known places. b.text(start, end) gives the bytes from start up to end as text, copied once, with no Bytes in between:

  • Places past the end are clamped, as a slice clamps them: end: 100 stops at the last byte.
  • Bytes that aren't valid UTF-8 give none, as b.text() does.
  • b[start:end].text() does the same, also copying the text once.

A fixed length

Bytes<len: 32> is exactly 32 bytes: a hash, a key, a field of a file format. crypto.sha256 gives one, so a function can say in its type that it returns a digest:

  • A Bytes<len: n> may go wherever Bytes may.
  • Plain Bytes become a Bytes<len: n> only through try or catch, which fails with a SizeError when the length is another.
  • a + b and the methods that make new bytes give plain Bytes.
  • The number in the type works as for lists: see Generics.

An index written as a number is checked while compiling:

Bytes([…]) of a list literal of n numbers is a Bytes<len: n>, so it doesn't fit another length:

In JSON

JSON has no bytes, so Bytes is written as base64 text, as Protocol Buffers' JSON and OpenAPI write them. Decoding reads the URL-safe alphabet too, with or without padding:

  • It holds for a bare value as for a field, and in lists, dicts and optionals.
  • Text that isn't base64 is a Mismatch error.
  • A spawn process passes Bytes this way too.
  • ask<T> still refuses Bytes: models write base64 badly.

Files are read as Bytes with fs.read_bytes, or in pieces with fs.chunks: see Reading files.
