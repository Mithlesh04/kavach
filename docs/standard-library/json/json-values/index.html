JSON: Json values

Also known as: dynamic type any unknown type duck typing schemaless untyped object dict mixed int float parse api response bigint decimal exact digits big number precision 0.1 lossless

● Intermediate4 min

A Json value holds JSON whose shape is known only while the program runs. It is a union of six cases, one for each kind of JSON value.

In simple terms

Sometimes data arrives and you don't know what it looks like, like a parcel with no label. A Json value can hold any of it, and tells you which of six kinds each piece is: a number, some text, a list and so on.

Being a union, match sees every case:

Every method

MethodGives
text()String?: the text of a Text
int()Int?: a Number written without a fraction or exponent that fits Int
bigint()BigInt?: a Number written without a fraction or exponent, of any size
float()Float?: a Number, as the nearest Float; none past Float's range
decimal()Decimal?: a Number, exactly
bool()Bool?: the value of a Boolean
list()[Json]?: the items of an Array
object()[String: Json]?: the fields of an Object
is_null()Bool: whether it is Null
len()Int: the items of an Array or fields of an Object, otherwise 0

Numbers keep their digits

A Number keeps the digits it was written with, exactly, so no number is changed by reading it and writing it out again. Each method reads it as the type you need, and gives none when it doesn't fit:

  • The id is too big for Int, so .int() gives none; .bigint() takes any size.
  • .decimal() reads 0.1 exactly, where a Float holds only the nearest number to it.
  • Written out again, both are the same digits that came in.

.float() reads any number, whole or not; "free" isn't a number, so it adds 0.0:

Parsing takes a number of any size. A number whose exponent puts it beyond 10^10_000, or below 10^-10_000, is out of range for .decimal() and .bigint() too, so a short text can't make a huge value:

JSON's null is the case Null. Kavach itself has no null: see Data Types for how it meets none.
