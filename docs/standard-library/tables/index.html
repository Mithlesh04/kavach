Tables

Also known as: table tables dataframe data frame pandas polars dplyr r spreadsheet excel rows columns column df group_by describe join pivot data analysis

● Intermediate8 minBefore this: Grouping and Statistics, RecordsSpec 14.34

std.table gives Table<R>: rows of a record type, for data read from CSV or JSON, as pandas and R's data frames are. It has the methods of a list of records, and the compiler checks every column a program names.

In simple terms

A table is a spreadsheet whose columns you named in a type. Because the type is known, a misspelled column is caught before the program runs, not after it gives a wrong answer.

use std.table brings in the module, written in Kavach in stdlib/table/. A type's fields are the columns; table.parse_csv<Sale> reads text into rows of Sale:

  • table.of(rows) makes a table of a list, table.read_csv<R>(path) reads a file, and table.parse_csv<R>(text) reads text, such as the body of a web response. CSV has every rule.
  • print(t) shows a grid: numbers to the right, text to the left, an empty optional as nothing, then the size.
  • Nothing about the data is guessed: the column types come from Sale, so month is an Int and note may be none.

Rows and columns

  • t[i] is row i, a Sale; out of range is a panic, as for a list. t.get(i) gives none instead.
  • A slice, t[0:2], t[#2:] or t[::-1], is a table of those rows.
  • t["amount"] is the column as a typed list, here a [Float].
  • A table is a value, as a list is: a copy shares its rows until one of them changes.

A column name is checked when the program is compiled. A name that isn't a field lists the ones there are:

Each field must be something a cell can hold: a number, Bool, Char, String, Decimal, a Date or DateTime, a category (a union whose variants have no fields), or an optional of one. A list, a record or a dict is a compile error that names the field:

The methods of a list

A table has every method a list of records has, with the same results (see Grouping and statistics). So code moves from a list to a table with no change. Where a list's method gives a list of records, a table's gives a table:

  • filter, sort_by, unique and unique_by give a table; group_by gives a dict of tables.
  • pivot gives a dict of dicts, as on a list, since its columns come from the data, and a table's columns must be known when the program is compiled. Its cell gets the table of the rows with both keys.

map to a record whose fields are cells gives a table; anything else gives a list. Adding a column is a map that writes every field again. An anonymous record's fields go in the order of their names, so the columns here are amount, region, tax:

inner_join and left_join take a table or a list, and give a table of the records row makes. In a left_join, the other row is optional, none when nothing matches:

describe() with no lambda sums up each number column, by name, in column order: count, mean, standard deviation, smallest, quartiles and largest. An optional column is left out. With a lambda, it sums up one column, as on a list:

JSON

JSON goes through std.json, with no second way. json.decode<[Sale]> reads an array of objects, and json.stringify(t) writes a table as one, a row each:

Not built yet: a table keeping its columns side by side. Today it keeps its rows as one list, and t["amount"] copies the column out when it is read; tensor.of(t["amount"]) copies it once more. Tables on the GPU are not built yet either.
