Running Programs

● Intermediate5 minBefore this: Capabilities, catchSpec 14.23

std.process runs other programs: a compiler, a simulator, git, any tool with no library. It needs the capability Process, never goes through a shell, and ends everything a program started when it stops.

In simple terms

Sometimes the tool you need is another program. std.process starts it for you, hands it its words exactly as you wrote them, and reads what it prints, like asking a colleague to run a job and report back.

  • process.run runs a program to its end and gives a Finished: its exit code, what it printed (out, err) and what it cost (cpu_ms, peak_bytes).
  • args is a list, passed as it is, never through a shell. "--version; echo injected" is one odd argument, so git refuses it: nothing else runs.
  • A program is a name looked up on the system's PATH, or a path such as ./tools/gen.
  • folder: sets the folder it runs in, and env: adds or changes its environment variables. It reads nothing on standard input.

It needs Process

Running a program reaches outside your own, so the function says so in its uses, or it doesn't compile:

Which programs

Process can be granted for one program, as Fs is for one folder. Inside a function with uses Process("git"), every program it runs, and everything it calls runs, must be git. Any other fails with Denied; a program that isn't there fails with NotFound:

WrittenAllows
uses ProcessRunning any program
uses Process("verilator")Only verilator
  • The name is checked when the program runs, since it is a value.
  • A name without a / matches only that name on PATH; a name with one matches only that path.
  • Names nest, as folders do: inside two, a program must match both. So a function that runs two tools has uses Process, or calls one function per tool.
  • A task keeps the names of the function that spawned it.

Output as it comes

process.start gives the program back running, as a Child. Its lines come one by one, each an Output.Out(line) or an Output.Err(line), without its line end. each calls a function with each one:

next() reads one line, and wait() waits for the end, skipping what is still printed:

  • An exit code of 0 most often means it went well. Git gives 129 for an option it doesn't know.
  • On Linux and macOS, a program ended by a signal gives 128 plus the signal's number, as shells say it.
  • Waiting for a line or for the end lets other tasks take their turns, so a program can run several tools at once, each in its own task.

A longer one, from the spec: a simulator whose errors are picked out of its output.

A program is a tree

What a program starts is part of it. kill(), a Child nothing holds any more, a task cancelled while it waits, and a time limit (.timeout) all end the whole tree: through a job object on Windows, and a process group on Linux and macOS. So a timeout never leaves a simulator running behind it.

What it cost

cpu_ms and peak_bytes say how long a program used the processor and the most memory it held, so a tool that runs too long or grows too big can be seen. process.peak_bytes() and process.cpu_ms() say the same of your own program, and need no capability:

Function or methodGives
