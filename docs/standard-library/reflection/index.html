Reflection

Also known as: reflection reflect introspection members methods fields has member has_method respond_to hasattr dir getattr typeof plugin origin extended builtin declared

● Intermediate5 minBefore this: Records, ExtendSpec 14.32

std.reflect tells a program what a type or a module offers: its members, each a field, method, function, type or constant, with its parameters, what it gives, and where it comes from.

In simple terms

A type's members are the things you can write after a dot: order.total, name.upper(). Reflection hands a program that list, so a tool, plugin or library can adapt to code it has never seen.

T.members() lists a type's fields and methods, sorted by name. Each is a Member: its name, its kind, its params and its result:

  • members(), has_member and module members() need no use: the compiler gives them to every type and module.
  • use std.reflect.{MemberKind} is only for naming the types, as MemberKind.Method here. They are declared in stdlib/reflect/reflect.kav.
  • A field's result is its type, and it has no params. A method's params leave out self.
  • Every list is worked out while compiling, so asking costs nothing at run time.
CallGives
T.members() -> [Member]Every field and method of type T: built in, declared in its body, or added by an extend, sorted by name. T is a type's name: String, Int, Order, and List, Dict, Set and Ring for collections
m.members() -> [Member]What module m offers to the code that uses it: its pub functions, types and constants, sorted by name
x.has_member(name) -> BoolWhether x's type has a field or method name; name is a text literal. For an interface value (2.15), whether the interface has it

Where a member comes from

origin says whether Kavach gives a member (BuiltIn), the type declares it (Declared), or an extend adds it, with the module that adds it:

The module is the file's name: extended for extended.kav. This finds every method a program added to a built-in type, for a tool that lists them or checks two modules don't clash.

Does it have this member?

x.has_member("name") answers for x's type, fields and methods alike, built in too: a list has len.

The name must be a text literal, as the compiler answers while compiling. A name from a variable is a compile error:

On an interface value, the answer is about the interface, not the value inside it. s holds a Square, which has side, but a Shape has only area:

Generic types and collections

A generic type's members show its type parameters by name: Box<T>'s get gives T. For the collections, write List, Dict, Set or Ring: T is the item type, and K and V a dict's key and value. The compiler knows a built-in method's parameter types but not their names, so they are named a, b and on:

What a module offers

m.members() lists a module's pub functions, types and constants. For a standard library module, that is the part written in Kavach: math.members() has gcd but not yet sin, which the compiler provides.
