Environment Variables

● Intermediate5 minBefore this: Settings, SecretsSpec 10.13

env(name) reads an environment variable. Its value is a secret, so it can't be printed by mistake. A .env file, kavach.toml or --env can give the values.

In simple terms

Environment variables are like notes the computer hands a program when it starts: which port to use, which key to send. Keys are private, so Kavach seals every such note: the program opens one only by writing reveal, on purpose.

env needs the Env capability, and it fails when the variable isn't set. What it gives is a secret, because keys and passwords usually come this way:

A value that isn't secret, such as a port, is opened with reveal, where review can see it:

  • Values are text, as environment variables are on every system: 8080 in [env.vars] arrives as "8080". The program converts it: Int(…), Bool(…), or split for a list written as text.
  • --env NAME=value beats [env.vars]: here the port became 9000 for one run.
  • A variable that isn't set fails, and catch gives a default, as SHOP_MODE does.

A list or a table in [env.vars] is refused, since a variable holds only text:

Without a value and without a default, the program ends with an error that names the variable:

A .env file

A .env file beside kavach.toml gives a program its variables without setting them in the shell. Never commit it: kavach new puts it in .gitignore.

  • Lines are NAME=value; export NAME=value works too. # starts a comment line. A value in double quotes may hold \n, \" and \\; in single quotes it is taken as written. Nothing is expanded: $HOME stays as written.
  • Any other line is an error that names the file and the line.
  • Another file: --env-file <path>, or file in [env]. A dependency's .env is never read.

Which value wins

Strongest first:

  1. --env given to kavach run or kavach test;
  2. the real environment: the shell, docker run -e, a service manager;
  3. [env.vars] in kavach.toml;
  4. the .env file.

So the place a built program runs always has the last word.

Built programs

  • kavach build copies the file, with [env.vars] and --env written into it, beside the executable: .kavach/bin/.env. Its values are never compiled in, since an executable is shared and copied. --no-env-file builds without one.
  • The executable reads that file the first time it reads a variable, so a program that never calls env pays nothing for it. A file it can't read, or a wrong line in it, ends the program there with exit code 2.
  • The variable KAVACH_ENV_FILE names another file, so a container can keep it elsewhere.

[env.vars] is committed with kavach.toml, so it is for settings such as a log level, never for keys. Keys go in .env, or in the real environment where the program runs.
