Automatic Memory: Memory, Step by Step

Also known as: memory layout heap stack allocation allocate reference count refcount rc arc copy on write cow move semantics ownership pointer share shallow copy deep copy does assignment copy new memory how much memory hash table hashmap index probe small string inline animation visualize

● Advanced10 minBefore this: Values, Not References, Automatic Memory: How it stays fast

Does let b = a take new memory? Step through what memory holds at each line: sharing, moving, copying on change, changing in place, for numbers, text, lists, dicts, sets and Shared.

In simple terms

Memory is where a program keeps its values. These pictures show its cells line by line, as on a real memory chip. Each value sits in cells, and a count says how many names hold it. When the count reaches 0, those cells are cleared for reuse.

Each picture is memory as it is: a memory stick, and one chip's cells close up, 8 bytes each. The stack's cells hold the function's names: a number sits right in its cell, a list or text holds the address of its object. The heap's cells hold the objects, each starting with its holder count: how many names, lists or other values hold it. Press Play, or step with Next.

The pictures follow spec 6.1 and how today's compiler and runtime lay values out. A program can't see a count, so a picture can't be checked by running it; what each program prints is checked.

Does b = a take new memory?

No. b = a never allocates. Values are copies to your code (values, not references), but in memory, b holds the same object, and its count goes up:

const a = [2, 3, 4, 5]
const b = a
print(`a={a}`)
print(`b={b}`)
The program prints, checked:
a=[2, 3, 4, 5]
b=[2, 3, 4, 5]

Numbers

A number is never an object, so b = a copies its 8 bytes, and a change to b leaves a:

const a = 7
let b = a
b += 1
print(`a={a} b={b}`)
The program prints, checked:
a=7 b=8
stack: the function's names

A number is kept in place, in the variable itself: 8 bytes, often in a register. No object, no count.

A change while shared: copied then

A value is copied only when it changes while something else still holds it. This is copy-on-write:

const a = [2, 3, 4, 5]
let b = a
b.push(6)
print(`a={a}`)
print(`b={b}`)

A change with no other holder: in place

When nothing else holds a value, a change is made where it is, with no copy. So items.push(x) or text += part in a loop adds only the new part each round:

for i in 0..3 {
    items.push(i * 10)
}
print(items)

The same holds for a list or dict in a field or in another list, and through inout: cart.items.push(x) and rows[i].push(x) change it where it is (how it stays fast).

Dicts and sets

A dict keeps its entries in the order they were added, each key and value in place. Past 8 entries, it keeps an index beside them:

let stock: {String: Int} = {:}
stock["tea"] = 3
stock["cake"] = 5
for i in 0..7 {
    stock[`item{i}`] = i
}
print(stock.len())
The program prints, checked:
9

step 1 of 5

A dict is one object with a count, like a list. It holds its entries in the order they were added.

  • A dict with whole-number keys keeps an index from the start. Its keys first use a cheap hash that keeps nearby keys nearby; if probes get long, by accident or by attack, it switches to a strong hash for good.
  • The hash's seed is chosen at random each run, so no one can work out in advance which keys collide.
  • A value inside, such as the list in {"a": [1, 2]}, is an object of its own that the dict holds. A copy of the dict shares that list too, until one side changes it.
  • A dict with a limit, {String: Int}<max: 100>, makes room for all its entries at once, so filling it never stops to grow.

Copying a dict works as for a list: shared until one side changes it.

const prices = {"tea": 3, "cake": 5}
let sale = prices
sale["tea"] = 2
print(`prices={prices}`)
print(`sale={sale}`)
The program prints, checked:

Shared: two names, one changing value

Shared is the one way two names see one value change. Copying it copies the handle, not the value:

const a = Shared([2, 3])
const b = a
b.update(list => list + [4])
print(a.get())

Frozen values and freeing

  • x.freeze() with no key is the same object, so freezing and unfreezing it costs nothing. A value sealed with freeze(key: k) is the pair (value, key) (frozen values).
  • An object is freed the moment its count reaches 0, when its last use ends. There is no garbage collector and no pause later.
  • A value whose type implements Drop lives to the end of its block, so its cleanup runs at a place you can see (freed immediately).
