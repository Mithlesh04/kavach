Kinds of Errors

Also known as: error types kinds of errors compile error warning runtime error exception panic crash bug parse error file not found network error

● Intermediate6 minBefore this: Reading ErrorsSpec 5

Kavach reports problems in four ways: compile errors and warnings before the program runs, errors and panics while it runs.

In simple terms

Think of checking a recipe before you cook: some problems are found while reading it, before anything starts. Others only show up while cooking: normal ones you planned for, like running out of milk, or real mistakes that stop everything.

The compiler refuses the program, says what is wrong, and usually what to write instead. Nothing runs.

A panic means the program itself is wrong: an index past the end, a division by zero, a broken contract. It stops at once instead of carrying on with a wrong value:

The rule of thumb: if it can happen in a correct program (the user typed rubbish), it is an error. If it can only happen in a wrong program, it is a panic.

Error types from the standard library

Each module that can fail has its own error type, a union you can match on:

ParseErrorReading text as a number, Bool or Char: Int(text)spec
FsErrorFiles: NotFound(path), Denied(path), Failed(path, reason)spec
NetErrorConnections: Refused, TimedOut, Failedspec
HttpErrorHTTP: the network, a bad URL, a bad message, an error status, or JSON that doesn't fitspec
JsonErrorJSON: bad syntax (with line and column), too deep, too large, a repeated key, or a field that doesn't matchspec
GrpcErrorgRPC callsspec

CliErrorCommand-line arguments that don't fitspec
AiErrorAsking an AI model: no key set, the provider refused, an answer of the wrong shape, or a limit said nospec
ErrorAny error at all: the catch-all for scripts and mainspec

Calls to a capability, such as Payments.refund, have one more case. Any of them can be refused, by a limit, by a person who says no, or because nothing implements the capability, so every capability's error type has the case Denied(reason: String), and the compiler insists on it. See When a call is refused.

Which error is inside an Error?

! Error accepts any error. A caller can still ask which one it holds, as Python's except FileNotFoundError or Go's errors.As do: name the type with each case.
