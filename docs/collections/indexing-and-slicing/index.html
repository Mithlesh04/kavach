Indexing and Slicing

● Beginner8 minBefore this: ListsSpec 2.19

xs[i] reads one item. xs[start:end:step] is a slice: a new list with the items from start up to, not including, end. #k counts from the end.

In simple terms

Think of a row of numbered seats. xs[2] is the person in seat 2. xs[1:3] is everyone from seat 1 up to seat 3, not counting seat 3. #1 means the last seat, however long the row is.

  • queue[0] is the first item: positions start at 0.
  • queue[#1] is the last item, queue[#2] the one before it.
  • A slice queue[start:end] holds the items from start up to, not including, end. A missing start is the first item, and a missing end is past the last.
  • A third part is the step: queue[::2] takes every second item, and queue[::-1] walks backwards.

The same brackets work on text, Bytes and text views:

A slice never goes out of range

Reading one item past the end is a panic, but a slice is clamped: a part past the end counts as the end, and a part worked out below 0 counts as before the first item. So a slice gives what there is:

Steps

A negative step walks backwards, as in Python: it starts at start and stops before it reaches end. With a negative step, a missing start is the last item, and a missing end is before the first:

A step of 0 would never move. Written in the code, it is a compile error:

Worked out while the program runs, it is a panic:

From the end: #k

#k is the place k from the end: len - k. It works in an index and at either end of a slice:

  • # covers the whole part after it, up to :, , or ]: xs[#n + 1] is xs[xs.len() - (n + 1)].
  • As the start of a slice, #0 is the end, so xs[#n:] with n of 0 is empty: the last 0 items.
  • #0 as an index is out of range, as xs[xs.len()] is.
  • # is written only inside [ ].

A plain number counts from the start

In Python, xs[-1] is the last item. Kavach counts from the end only with #, so a written negative number is a compile error that names the # form:

Text

Text is indexed and cut by characters, as len() counts them, so a letter such as é is one place. s[i] is a Char, and a slice of text is text:

A slice of a String is a copy. s.view()[a:b] is a view of those characters, with nothing copied: see Text views and builders.

A slice is a new value

Changing a slice never changes the list it came from, and changing the list never changes the slice:

Setting a slice

xs[a:b:step] = ys replaces the items the slice names with the items of ys, in order. The list must be a let. # works where one item is set, too:

ys must have as many items as the slice, so setting a slice never makes a list longer or shorter: push, pop, += and remove do that. Another length is a panic that names both:

The slice is clamped first, then the lengths are compared. When nothing else holds the list, it is changed in place.

Lists of lists

A list of lists is read one level at a time: rows[1][2] is item 2 of row 1.

A list has one dimension, so one pair of brackets takes one part:

A tensor has as many dimensions as its shape, and takes one part for each, separated by commas, as NumPy writes them: t[1, 2], t[:, #1]. See Tensors: Indexing.

A dict has keys, not places, so it has no slices:

No methods that slice

A slice is written only with brackets. The methods that did a slice's job are gone, and each one is a compile error that names the bracket form:
