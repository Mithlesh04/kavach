Lists

Also known as: array vector arraylist slice append index element push pop collection sequence

● Beginner5 minBefore this: For Loop, VariablesSpec 2.2

A list holds many values of one type, in order, under one name: ["mango", "fig"].

In simple terms

A list is like a numbered shopping list: many things of one kind, in order, under one name. You can add to the end, and find an item by its place, where the first place is 0.

  • Square brackets make a list. Its type is written [String]: a list of strings.
  • fruits[0] is the first item: positions start at 0.
  • push adds to the end. It changes the list, so the list must be a let.

All the items of a list have the same type. To group values of different types, use a tuple or a record. Lists of lists, lists of dicts, and items of different kinds through a union are in Nested and Mixed Collections.

What the machine does

A list is two pieces of memory: a small object that knows where the items are and how many there are, and a buffer with the items side by side. Step through reading, adding and slicing:

The runtime makes the list while running, in two pieces: a 48-byte list object (a 24-byte header with the count, then the buffer's address, the length and the capacity), and apart from it a buffer of exactly 3 slots. Whole numbers sit in the buffer itself, 8 bytes each: no object per item.
Drawn for kavach run --native. Every object starts with the same 24-byte header: the count, then words saying what kind of object it is and its type. "room" is space the buffer has but doesn't use yet; "·" alone is free memory. A list written out gets room for exactly its items, as here; a list of small numbers, packed, rounds that up to whole 8-byte words: [UInt8] of 3 has room for 8, [Int32] of 3 for 4. Addresses are examples: they differ on every run.
Every step, as text
  1. Line 1: let xs = [3, 1, 4]
    The runtime makes the list while running, in two pieces: a 48-byte list object (a 24-byte header with the count, then the buffer's address, the length and the capacity), and apart from it a buffer of exactly 3 slots. Whole numbers sit in the buffer itself, 8 bytes each: no object per item.
  2. Line 2: print(xs[1])
    Reading xs[1]: code the compiler wrote checks the index with one compare, 1 < len 3. A negative index counts as a huge unsigned number here, so the same compare catches it too. Then one load from ptr + 1 × 8 = 0x2008 gives 1.
  3. Line 3: xs.push(5)
    push checks two things inline: the count is 1, and len < cap. 3 < 3 is false, so the code calls the runtime. The runtime, while running, grows the buffer the way Rust's Vec does: room for 6, double. 5 goes in slot 3, len 4. A bigger buffer may move to a new address, with the items copied there: the allocator decides that, while running. It is drawn in place.
  4. Line 4: xs.push(9)
    Now there is room: count 1 and 4 < 6, so the code the compiler wrote stores 9 at ptr + 4 × 8 and sets len to 5. The runtime isn't called at all.
  5. Line 5: const firsts = xs[:2]
    A slice is a new value: the language says so, and the runtime copies at once, while running. It makes a new list object and a buffer of exactly 2 slots, and copies 3 and 1 into them. xs is not changed: still count 1.
  6. Line 6: xs[0] = 7
    Setting an item checks the same way inline: count 1, and 0 < len 5. 7 goes in place at 0x2000. firsts still holds 3: it is a copy, not a view of xs.
  7. Line 7: print(firsts)
    firsts' last use, marked by the compiler while compiling: print takes the list and lets it go. Its count falls to 0, so the runtime frees its object and buffer while running. They go grey where they were.
  8. Line 8: print(xs)
    xs's last use, also marked by the compiler: freed the same way. Nothing searched for garbage: each list was let go at its last use.

Go deeper the why, for readers who want it
Two things make Kavach lists fast. Values never alias: a list always has one owner, so the compiler can keep it in registers and skip defensive copies. And lists of small items are packed, so more items fit in each cache line:
