Operators for Your Types

● Intermediate9 minBefore this: Interfaces, OperatorsSpec 2.16

A type gets +, -, *, /, %, ** and < by implementing Add, Sub, Mul, Div, Rem, Pow or Comparable. Then vectors, money and units read like numbers.

In simple terms

Numbers can be added with +. Your own type can be too, once it says how: you write an add method, and a + b calls it. Nothing happens by magic, and a type without the method has no +.

  • type Vec2: Add, Neg, Mul<Float> says which operators the type has, as with any interface.
  • a + b calls a.add(b), -b calls b.neg(), and a * 2.0 calls a.mul(2.0).
  • c += a is c = c + a, as for numbers, so it needs Add and a let.

The other operand

Add alone takes the same type and gives it back. Mul<Float> takes a Float instead. With a second type argument, the result is another type: Mul<Meters, Area> takes Meters and gives an Area:

Ordering with Comparable

Comparable gives <, <=, > and >= from one method, compare: below 0 when self comes first, 0 when neither does, above 0 when the other does:

compare gives a sign, not a distance

a.compare(b) answers one question: which comes first? Only the sign of the answer counts, not its size:

  • Below 0: a comes first, so a < b is true.
  • 0: neither comes first, so a <= b and a >= b are both true.
  • Above 0: b comes first, so a > b is true.

Numbers and text always give -1, 0 or 1. So 7.compare(9) is -1, not 7 − 9 = -2, and 7.compare(100) is -1 too: 7 comes first both times. Your own type may give any number with the right sign. Money's compare gives the difference in cents, -45 here, and < reads only that it is below 0:

Text comes first in alphabetical order, character by character: "apple" before "pear". A float's compare gives 0 when neither comes first, as with a NaN.

== and != are not interfaces: they compare contents for every type. So a == b and compare disagree only if the type's author makes them.

Comparisons that give something else: Compare

Compare<R, Out> gives each of < <= > >= its own method, lt, le, gt and ge, with a right operand of type R and a result of any type Out. A tensor's t > 0.5 gives a mask this way:

A type implements Comparable, for an order, or Compare, not both, as < would have two meanings. Compare may be implemented several times, once for each right operand:

MatMul gives @, the matrix product: see Tensors and Matrices.

Operators in generic code

A type parameter with an operator's interface as its bound may use that operator. The number types meet Add, Sub, Mul, Div, Rem, Neg and Comparable as they are, and String meets Comparable. So one generic function serves numbers, text and your own types. Three functions, each asking for one operator, called with each kind of value:

Each function asks for only the operator it uses:

  • total<T: Add> adds every item to zero. It takes zero as a parameter because a plain Add has no way to make a zero: it is 0 for Int, Float32(0.0) for Float32 and Money(cents: 0) for Money. Numbers add with their own +; Money adds with its add method.
  • flip<T: Neg> uses unary -: a number turns negative, and Money calls its neg method.
  • largest<T: Comparable> keeps the item that comes last in order, using >. Numbers compare by size, text in alphabetical order (so "zebra" wins), and Money by its compare method. An empty list has no largest item, so it gives none.
  • Each type a function is called with gets its own compiled copy, so for a number a + b is one machine instruction, as if you had written the function for that type.
  • A number's methods are the operators, so a number meets these bounds: 7.add(2), the last line, is 9, the same as 7 + 2. Its compare is its ordering: 7.compare(9) is -1, as 7 comes first (see above).
  • For any number at all, T: Number gives every operator at once: see Generics.

Indexing and slicing

x[k], x[k] = v and x[start:end:step] (see Indexing and Slicing) come through interfaces too:

InterfaceWrittenThe method
Index<Key, Out>x[k]fn index(self, key: Key) -> Out
IndexSet<Key, Value>x[k] = v, x[a:b] = vfn index_set(self, key: Key, value: Value) -> Self: x[k] = v is x = x.index_set(k, v)
Slicex[start:end:step]fn slice(self, part: Part) -> Self
Slice<Key>x[a:b, c:d]fn slice(self, part: Key) -> Self, where Key is a tuple of Parts
  • p[0] calls p.index(0), and p[1] = "storm" is p = p.index_set(1, "storm"), so it needs a let, as += does.
  • p[#1] is p.index(p.len() - 1): # needs a method fn len(self) -> Int.
  • slice is given a Part: what was written between the brackets, with none for a part left out.
  • Like the other operator methods, these are pure. An index out of range may panic, as a list's does.

Setting a slice, r[1:3] = v, calls index_set too, with the slice's Part as its key. A type may implement IndexSet once for each pair of key and value types, so it can take a number at one key and a list at a slice:

Part is a record of std.collections, written in Kavach, which every file sees without a use. part.bounds(len) gives its start, end and step as plain numbers for len items, as Python's slice.indices does: #k becomes len - k, a missing step is 1, the missing ends are filled in, and both ends are clamped:

With a negative step, an end of -1 means before the first item, so a slice of a list made from those numbers walks back to the start, as Playlist's does. A step of 0 is a panic. Without len, # is refused:

Parts separated by commas give a tuple key: g[1, 2] is g.index((1, 2)), for a type with Index<(Int, Int), Out>. When every part is a slice, g[0:2, 1:] is g.slice((first, second)), two Parts, for Slice<(Part, Part)>.

A type with any number of dimensions, as a tensor, takes a key of any length: a list of Parts, through Index<[Part], Out>, IndexSet<[Part], Value> and Slice<[Part]>. Each place between the commas is one Part: a number i is Part(start: i, single: true), and #k has start_from_end set, so it counts from the end of its own dimension. A key of numbers only calls index; a key with a slice calls slice:

A type may implement Index once for each type of key, and the key's type picks the method while compiling: a tensor has one index for a list of Parts and one for a mask.
