Extend

Also known as: extend extension method monkey patch add method to existing type implement interface for prototype array list map set ring generic

● Intermediate4 minBefore this: MethodsSpec 2.5

extend adds methods to a type you didn't write: a built-in type, a list or dict, a union, or a type from another module.

In simple terms

Like adding new buttons to a machine you bought, without opening it up: extend gives a type new actions, even a type you didn't make. It adds actions only, never new data.

Inside extend, methods are written as in a record, with self. A union's methods go in an extend too, since a union has no body of its own.

Extending a generic type

To extend a generic type, name its parameters after extend, as a generic function does: extend<S> App<S>. So a type's many methods can be spread over files:

  • S stands for the type's own parameter: state_of gives a String for one app and an Int for the other.
  • A name after extend that isn't one of the type's parameters is an error.

Lists, dicts, sets and rings

Collections take methods too. Name each item type after extend: extend<T> [T], extend<K, V> {K: V}, extend<T> Set<T> or extend<T> Ring<T>. The methods then work for every item type, and T is the item type of the one called on:

A range has a list's added methods, as it has a list's own. The methods are for every list, so an item type written out is refused:

Methods are added, never changed: a method with the name of one the collection already has is refused, so xs.len() always means the same.

Keeping a promise for another type

extend Rect: Describe { … } says that Rect, declared elsewhere, keeps the Describe interface:

extend adds methods, never fields: a type's data is always where the type is declared.
