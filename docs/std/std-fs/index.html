What the spec lists

FunctionGives
fs.read_text(path) -> String ! FsErrorThe file's text (it must be UTF-8)
fs.write_text(path, text) ! FsErrorReplaces the file atomically: the new text goes to a temporary file that is then renamed, so a crash never leaves half a file
fs.append_text(path, text) ! FsErrorAdds to the end, creating the file if needed
fs.read_bytes(path) -> Bytes ! FsErrorThe file's contents, any bytes (2.13)
fs.write_bytes(path, data) ! FsErrorReplaces the file atomically, like write_text
fs.write_durable(path, data) ! FsErrorReplaces the file atomically and forces it to the disk (fsync on the file, then on its folder) before returning: after it, a power cut keeps the new contents. Storage engines build on this
fs.lines(path) ! FsErrorThe file's lines, read as a for loop goes, without their line ending (\n or \r\n)
fs.chunks(path, size) ! FsErrorThe file's bytes in Bytes pieces of size (the last may be shorter), read as a for loop goes
fs.exists(path) -> BoolWhether a file or folder is there
fs.list(folder) -> [String] ! FsErrorThe names in a folder, sorted
fs.remove(path) ! FsErrorDeletes a file or an empty folder
fs.create_dir(path) ! FsErrorCreates a folder and any missing parents
fs.info(path) -> FileInfo ! FsErrorWhat is at path: its kind, size, last change and permissions (below). A link is described itself, not what it points to
fs.set_read_only(path, read_only) ! FsErrorMakes a file read-only, or writable again, on every system
fs.set_permissions(path, mode) ! FsErrorSets the Unix permission bits, written in octal: 0o644, 0o755. Windows keeps only whether the owner may write: without that bit the file is read-only
fs.rename(from, to) ! FsErrorMoves or renames a file or folder; a file already at to is replaced
fs.copy(from, to) ! FsErrorCopies a file, with its permissions; a file already at to is replaced
fs.remove_all(path) ! FsErrorDeletes a folder and everything in it, or a file
fs.symlink(target, link) ! FsErrorMakes a symbolic link at link that points to target, kept as written (a relative target is relative to the link's folder). With uses Fs("…") (8.1) both must be inside its folders. Windows allows it only in Developer Mode or with administrator rights; otherwise it fails with Denied
Function or methodGives
fs.create_writer(path) -> FileWriter ! FsErrorA new, empty file at path to write; one already there is emptied
w.write(data) ! FsErrorAdds the Bytes data at the file's end. Writes are gathered in memory and go to the file 64 KB at a time
w.write_text(text) ! FsErrorThe same for text, as UTF-8
w.finish(sync: false) -> Int ! FsErrorWrites what is gathered, closes the file, and gives how many bytes it holds. With sync: true it also forces them to the disk (fsync), so a rename after it can't leave a short file after a crash
Function or methodGives
fs.watch(path) -> Watcher ! FsErrorWatches the file at path, or the folder and everything in it. Fails with NotFound when there is nothing there
w.next() -> FileChange?The next change, waiting for one; none once the watcher is closed
w.poll() -> [FileChange]The changes that came since the last call, without waiting; empty when none did
w.close()Stops watching; a watcher stops anyway when its last holder ends
