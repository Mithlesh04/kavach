A declaration below shows what a program writes against: a type's fields, a function's parameters, what it gives, its contracts (require, ensure) and its examples. kavach test runs every example, so each one is true of the code.

FunctionGives

What is tested

Each conformance test in tests/conformance/ checks one rule of spec 14.14. 16 tests: 15 check that it works, 1 that wrong use is refused.

RuleSpecChecksTest
a plain grpc.call to a method that answers with a stream gives the stream's first message.14.14worksgrpc-a-plain-call-to-a-stream-gives-the-first
a gRPC call to an address nobody listens at fails with GrpcError.Network, holding the NetError.Refused of that address.14.14, 14.10worksgrpc-a-server-nobody-runs-is-a-network-error
grpc.call<Req, Res> calls a gRPC method with a typed request and decodes the typed answer; grpc.serve answers each call with its handler, and a status other than OK fails the call with Status.14.14worksgrpc-calls-from-types
gRPC calls need the Net capability, so calling one from a function whose uses clause doesn't list it is a compile error.14.14, 8.1refused: compile errorgrpc-calls-need-net
grpc.call_stream sends each request as its own message on one call, the handler gets them all in call.messages (grpc.read_all), call.message is the first, and the one answer is decoded as with grpc.call.14.14worksgrpc-client-streams-send-every-message
grpc.failed(code, message) ends the call with that gRPC status, and the client's call fails with Status holding the same code and message, whatever characters it has.14.14worksgrpc-failed-keeps-its-code-and-message
fields added at the end of a record keep older code working: a newer server reads an older request, its missing fields taking their default, none or zero value, and an older client reads a newer answer, skipping fields it doesn't know.14.14worksgrpc-fields-added-at-the-end-keep-old-sides-working
grpc.encode<T> builds JSON before its Protocol Buffers, so a secret field goes into the message as "<secret>", never its value.14.14, 8.7worksgrpc-hides-secret-fields
a map field with String keys travels as Protocol Buffers' map encoding — a repeated entry message per key, the key as field 1 and the value as field 2 — and json.schema gives such a map {"type": "object", "additionalProperties": …}.14.14, 2.12worksgrpc-maps-use-entry-messages
grpc.encode<T> writes a value as a Protocol Buffers message whose field n is the type's nth declared field, and grpc.decode<T> reads it back.14.14worksgrpc-messages-are-protocol-buffers
a Protocol Buffers message that isn't one of a T fails with GrpcError.BadMessage: a message cut off, a request of another type read by the server, an answer of another type read by the client.14.14worksgrpc-messages-that-dont-decode-are-bad-message
in a gRPC message the sized integers travel as int64, so a negative Int32 takes ten bytes, UInt64 travels as uint64, and a list of booleans is packed.14.14worksgrpc-sized-integers-travel-as-64-bit
a handler answering grpc.reply_stream(values) sends each value as its own message on one stream, and grpc.each runs its function for every message as it arrives, returning on status OK and failing with Status otherwise.14.14worksgrpc-streams-deliver-each-message
on a method in grpc.serve_talks's list, the handler answers each message as soon as it arrives, and grpc.talk_with runs its function for each answer as it arrives, sending what it gives next, and ending its side when it gives none; so each side can answer the other's last message.14.14worksgrpc-talks-answer-as-messages-arrive
grpc.each_stream sends each request as its own message on one call, then runs its function for each message of the answer as it arrives, returning on status OK and failing with Status otherwise.14.14worksgrpc-two-way-streams
a union field travels as a wrapper message holding a oneof: counting fieldless variants first, variant k is field k — an empty message for a fieldless variant, the variant's fields as a message otherwise; a union that never arrived fails to decode.14.14worksgrpc-unions-are-oneof-messages
