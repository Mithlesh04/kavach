Agents in Practice

Also known as: benchmark tokens cost langchain agentexecutor tool calling structured output prompt injection refund triage insurance health devops legal contract logistics shipment real world comparison python

● Intermediate10 minBefore this: Agents, ask<T>Spec 8.4

Real AI tasks from support, retail, insurance, health care, operations, law and logistics, measured against Python done the usual ways: the same inputs, the same models, the same right answers. Kavach's goal: fewer tokens, no worse answers, less time.

In simple terms

This page is a fair race: the same real tasks, done in Kavach and in Python's usual ways, with the same AI and the same right answers. It counts the tokens each way pays for, the time it takes, and how often it is right.

Fewer tokens is a smaller bill. The time comes from asking together: every item waits for the model at the same time, instead of in a queue. The answers aren't always the same: each case below says how many every way got right.

The ways compared

KavachOne ask<T> per decision, for a checked value of type T. Agents' limits and approves keep the rules, so the model never has to. In the complex case, three agents use the model their step needs (model quick(), model careful(), decision 0056).
Kavach, all at onceThe same, with each item in a task of its own (spawn), so the calls wait for the model together.
Python, plain promptA prompt that asks for JSON, parsed and checked by hand, and asked again when it doesn't fit; the rules (over 500, over 2,000) written in code next to it.
Python, tool callThe answer as a forced tool call, the way frameworks give typed output (LangChain's with_structured_output). Small, health-records and legal cases.
Python, agentic tool loopAn agent loop as frameworks run one (LangChain's AgentExecutor, the SDK's tool runner): the policy and the tools go to the model, it calls one, gets the result back and answers again, until it stops. Large, complex, DevOps and logistics cases.

Every way gets the same inputs and the same expected answers, and uses the same models. A proxy in front of the API counts the tokens of every call, for every way the same.

What the usual ways risk

  • A plain prompt gives text. A missing field or a misspelled choice reaches the program unless someone writes the check, every time.
  • A rule like "over 500 needs a person" must be repeated at every place that pays. In Kavach it is one limit, checked on every call: see limit.
  • An agentic tool loop trusts the model to choose the action; an injected note is stopped only if each tool checks for itself, and it pays for that in tokens.

Measuring found two things Kavach now handles: a provider turns away too many calls at once, so a busy or dropped call is sent again after a growing wait (see When the AI fails), and asking for the type in the prompt costs a third of the tokens of structured output (see ask<T>).
