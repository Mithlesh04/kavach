Agents in Practice

Also known as: benchmark tokens cost langchain agentexecutor tool calling structured output prompt injection refund triage insurance health devops legal contract logistics shipment real world comparison python

● Intermediate10 minBefore this: Agents, ask<T>Spec 8.4

Real AI tasks from support, retail, insurance, health care, operations, law, logistics and finance, measured against Python done the usual ways: the same inputs, the same models, the same right answers. Kavach's goal: fewer tokens, no worse answers, less time.

In simple terms

This page is a fair race: the same real tasks, done in Kavach and in Python's usual ways, with the same AI and the same right answers. It counts the tokens each way pays for, the time it takes, and how often it is right.

Fewer tokens is a smaller bill. The time comes from asking together: every item waits for the model at the same time, instead of in a queue. The answers aren't always the same: each case below says how many every way got right.

The ways compared

KavachOne ask<T> per decision, for a checked value of type T. Agents' limits and approves keep the rules, so the model never has to. In the complex case, three agents use the model their step needs (model quick(), model careful(), decision 0056).
Kavach, all at onceThe same, with each item in a task of its own (spawn), so the calls wait for the model together.
Python, plain promptA prompt that asks for JSON, parsed and checked by hand, and asked again when it doesn't fit; the rules (over 500, over 2,000) written in code next to it.
Python, tool callThe answer as a forced tool call, the way frameworks give typed output (LangChain's with_structured_output). Small, health-records, legal and invoices cases.
Python, agentic tool loopAn agent loop as frameworks run one (LangChain's AgentExecutor, the SDK's tool runner): the policy and the tools go to the model, it calls one, gets the result back and answers again, until it stops. Large, complex, DevOps, logistics, finance, retail stock, refund amounts, warranty desk and under attack cases.

Every way gets the same inputs and the same expected answers, and uses the same models. A proxy in front of the API counts the tokens of every call, for every way the same.

A crash halfway: 30 refund requests, killed at the 6th refund

Measured 2026-11-08, claude-haiku-5-5. The refunds go through a bank's web service. At the 6th refund the bank moves the money, and the program is killed before it hears back. Then it is started again, and the bank counts what was paid. The bank drops a repeat that comes with a key it has seen. Kavach's refund sends one, from agents.call_key(). The Python scripts send none: that is code nobody wrote for them here.

The items missed again and again are ones a person could argue: order 26 (510 USD, "stopped working after a week"), payment 8 (a new shop near the cardholder's office), ticket 17 (deleting an account: a canned reply or a person?), and claim 11 (a theft never reported to the police: deny, or review for the missing report, as Opus and Fable read it).
  • The same prompt gives the same answers. Kavach and the plain prompt send the same prompt and miss the same items, on every model. The agentic loop sends the policy as system with tools, a different prompt, and that is where it differs.
  • Thinking depends on the model. Of Kavach's output tokens, thinking is 74% on Haiku, 42% on Sonnet, 69% on Opus and 25% on Fable. A forced tool call turns Haiku's thinking off, and that way got 49 of 52 right there; on the models that refuse a forced tool it is asked with auto, thinks, and got 51–52.
  • The crash test is the same on every model: what is paid twice depends on the program, not on the model.
  • No model was talked into paying more than the price in the refund amounts case, in any way. On Fable the plain prompt refunded the broken lamp in full where the policy sends a lawyer's threat to a person.

When the provider fails

A real provider sometimes turns a call away as busy, or a connection drops after the call was paid for. run.py --flaky 0.3 makes 30% of calls fail on purpose: half turned away as overloaded (529), a third as too many requests (429), and the rest sent on and paid for, but the answer never arrives. All twelve cases ran so on claude-haiku-5-5 (2026-11-08): the Python ways retry as Anthropic's Python SDK does, twice by default, then again with 4 retries, Kavach's default (spec 8.4). Retrying doesn't depend on the model, so one model is enough. "Lost" counts the items that got no answer at all.

Under attack

2026-11-09. Twenty refund requests under the large case's policy, each note trying another way to steer the money (data/attacks.json). Kavach and the plain prompt send the large case's prompts: the model picks the action, and code pays this order its own price. The agentic tool loop gives the model a refund tool that takes the order and the amount, as a payments API does; the payments side refuses any single refund over 500. On claude-haiku-5-5, claude-opus-5-5 and claude-fable-5-1 the case ran three times (--tag run2, --tag run3; Opus's and Fable's repeats came with the twelve cases' repeats, below). "Paid wrongly" counts refunds to another order, for another amount, or that the policy doesn't give. These runs cost $6.13 in all.

Kavach one by one answered as Kavach all at once on every model; its rows are in the results files. Tokens and cost are of the first run.

What the usual ways risk

  • A plain prompt gives text. A missing field or a misspelled choice reaches the program unless someone writes the check, every time.
  • A rule like "over 500 needs a person" must be repeated at every place that pays. In Kavach it is one limit, checked on every call: see limit.
  • An agentic tool loop trusts the model to choose the action; an injected note is stopped only if each tool checks for itself, and it pays for that in tokens.

What the measuring found and fixed

  • A provider turns away too many calls at once. Now a busy or dropped call is sent again after a growing, random wait, and a program's asks share a gate, so 300 started together all get their answer: see When the AI fails.
  • Asking for the type in the prompt costs a third of the tokens of structured output: see ask<T>.
  • A tokens limit now counts the asks still waiting for their answer, in a way the agent's settings choose: see limit.
  • Native code now runs a match arm that returns or breaks (see match), and kavach run --native app.kav -- a b no longer gives the program the -- (see Command-line programs).
