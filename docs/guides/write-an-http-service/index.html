Write an HTTP Service

● Intermediate14 minBefore this: HTTP: Serving, HTTP: JSON over HTTP, Shared State

One task from start to finish: a small JSON service that keeps a shop's stock. It answers GET and POST, says clearly what is wrong, shares one value between requests, and is tested without a network.

In simple terms

A web service is a program that waits for questions sent over the network and sends back answers. Here the question is "how much tea is left?", and the answer is a little JSON.

The service keeps a count for each item. GET /stock/tea gives tea's count; POST /stock with {"item": "cake", "count": 5} sets one. Every piece of code and every output on this page comes from one project the site runs.

2. One function answers every request

A handler is a plain function from a Request to a Response. Its routes are ifs on the method and the path. Each mistake gets its own status and a sentence that says what to send instead:

  • An item it doesn't have is 404. A body that isn't a Stock, or a count below zero, is 400, and changes nothing.
  • stock is a Shared value: the one value every request sees. update changes it with no other request in the middle, so two requests at once never lose a change.
  • handle has no uses, so it can't read a file or open a connection; at most it could print, as every function may. The compiler holds it to that, so what it does is all on the page.

3. Serve it

main listens on a free port of this machine, serves handle, and then calls the service itself, as a client would:

  • 127.0.0.1:0 asks for any free port on this machine; listener.address() says which it got.
  • The handler is a lambda that passes stock along with each request.
  • http.serve runs until the function that started it returns, which stops it: nothing is left running.
  • In a kavach build, each connection is handled on any core of the machine, at once (see Serving).

4. Run it

http.get_json<Stock> reads the answer straight into a Stock, so the client is typed as well.

5. Test it without a network

A handler is a function, so a test calls it with a Request it builds, and no port is opened. A test file beside stock.kav is part of that module, so it sees handle and its imports:

handle takes a Request and a Shared, which kavach test can't make up yet, so it says so instead of skipping it quietly: the two tests above are what check it.

6. Before it faces the internet

  • Each client is already held to limits on time, size and connections, with safe defaults. Change them with ServeLimits (see Limits).
  • kavach build makes one program to copy to a server; its runtime is inside it.
  • Keep the stock somewhere that lasts, such as a database, when it must survive a restart: a Shared value lives as long as the program.
