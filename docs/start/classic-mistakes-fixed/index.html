Classic Mistakes, Fixed

Also known as: 0.1 + 0.2 floating point error precision rounding nan overflow wrap javascript quirks gotchas pitfalls wat parseint big decimal bigdecimal bigfloat

● Beginner8 min

0.1 + 0.2 is 0.3, a NaN can't break a sort, "😀" is one character long: the everyday traps of other languages, fixed.

In simple terms

Every language has hidden traps: the program runs and gives an answer, but the answer is quietly wrong. Kavach fixes the best-known ones, or stops with a clear message instead of carrying on with a wrong answer.

Every language has traps where a program runs, gives an answer, and the answer is wrong. Here are the best known, what other languages do, and what Kavach does. Every Kavach answer below was printed by the real compiler when this site was built.

Numbers

0.1 + 0.2

Elsewhere: C, Java, JavaScript, Python and Rust all print 0.30000000000000004.

The compiler works numbers written in the code out exactly, then rounds once. Values computed while the program runs still round at each step, as on every computer: for money, use Decimal, which is always exact and has no size limit.

Integers that wrap around

Elsewhere: C, C++, Java and Go wrap silently. The JDK's binary search broke on huge arrays because (low + high) / 2 overflowed into a negative index.

Overflow is checked in every build, so the bug stops at its line instead of giving a wrong index. When the numbers are known while compiling, as in (1_500_000_000 + 2_000_000_000) / 2 on Int32, it doesn't even compile: "this always panics".

A NaN in a list breaks sorting

Elsewhere: C++ has undefined behaviour; Java, JavaScript and Python leave the list half sorted.

A NaN ("not a number") sorts after every number, in sort, sort_by, min and max.

NaN turned into a whole number

Elsewhere: Undefined behaviour in C; Java and Rust quietly give 0.

"1" + 1

Elsewhere: JavaScript gives "11", and "10" * "2" gives 20.

Types never change behind your back; convert on purpose with String(1) or Int("1").

Text read as a number

Elsewhere: JavaScript's parseInt("23sd") is 23.

Int(text) reads the whole text or fails, and you say what happens then.

Also fixed: x % 2 == 1, which misses negative odd numbers, gets a warning; == between computed floats gets a warning pointing to a.near(b); a constant too big for its type is a compile error that names a type that fits. Where C and Python disagree on -7 / 2, Kavach has both: / and % as C, div_floor and mod as Python (see Arithmetic). See Kinds of Errors.

Text

Length, capitals and sorting

Elsewhere: In JavaScript, Java and C#, "😀".length is 2. JavaScript's default sort puts [10, 9, 1, 2] in the order [1, 10, 2, 9].

Text counts characters; "ß" in capitals is "SS", as Unicode says; numbers sort as numbers.

Values

A default argument shared between calls

Elsewhere: In Python, def add(x, items=[]) keeps one list for every call, so the second call returns [1, 2].

A closure that sees the loop's last value

Elsewhere: JavaScript with var, and Go before 1.22, print 3 3 3.

A lambda keeps a copy of each value it uses, taken when it is made.

Two names for one list

Elsewhere: In Python, Java and JavaScript, b = a shares the list, so changing b changes a.
