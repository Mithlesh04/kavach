Why a new language

Why build a new language at all?+

Because of one problem that kept coming up. More and more code is written by AI, and more of it runs as agents that do real things: refund an order, email a customer, change a record. In Python, Go or TypeScript, nothing in a function tells you what it can touch. You find out by reading every line, or after something goes wrong.

In Kavach that is part of the code. A function says what it uses (uses Fs, uses Net), the compiler checks it, and an agent's limits sit right next to it. That's very hard to add to an existing language without breaking the code already written in it.

Couldn't this just be a library for Python or TypeScript?+

Partly, and guardrail libraries for agents do exist. The difference is where the check happens. A library checks what you remember to send through it. In Kavach the compiler refuses a function that reaches the network without saying so, and that includes code you didn't write yourself: a package, or something an AI generated.

Limits, approvals and the audit log are run by the runtime, so a missing line of glue code can't switch them off. What Kavach Does for You lists each check, with the test that proves it.

Who is it for?+

Mainly teams putting AI agents into production, and backend developers who want native speed without memory bugs. It also works as a first language: the course starts from what a program is.

It isn't trying to replace notebooks for data science, and it isn't a no-code tool. More on who Kavach is for.

When AI writes the code

If AI writes most of the code, why learn Kavach?+

Because someone still decides what the code is allowed to do, and checks that it does only that. That job doesn't go away when an AI types the lines. It gets bigger.

Kavach is built for that job. You write an agent's limits and approvals yourself, and a function's first line says what it takes, what it gives back, how it can fail and what it can touch. So reviewing AI code is mostly reading signatures and contracts, not every line. Reading Kavach well is the skill, and it's quick to pick up.

AI models weren't trained on Kavach. Can they write it?+

Not on their own, and we measured it. Given only the task, Claude models wrote a working program 4% to 8% of the time. Given Kavach's one-page guide for AI tools, llms.txt, that went up to 88% to 97%. With Kavach's own tools through kavach mcp, so the model can check and run its code, it reached 100%. The same models got 100% on the same tasks in Python.

The language helps: the grammar is small and regular, and every compiler error says what to write instead, which is what a model needs when it fixes its own code. The whole run, failures included, is on How Well AI Writes Kavach.

Which AI assistants and editors work with it?+

Any assistant that can read a web page can read llms.txt. Assistants that speak MCP, such as Claude Code or Cursor, can run kavach mcp to check, run and test code, and look things up with kavach outline and kavach query instead of reading whole files, which saves tokens.

For editors there is a VS Code extension in the repository, with highlighting, and errors as you type from kavach lsp. See Tools for AI.

Trust and production

Is Kavach ready for production?+

Not yet, and it's better to say that plainly. Kavach is before its first public release: the core language (Phase 1) is done, and agents (Phase 2) are under way. The compiler builds native programs on Windows and Linux, agents work end to end, and every conformance test passes in the interpreter and in native code. But the language can still change, and there is no stability promise until version 1.0.

Use it to learn, to try ideas and for internal tools. Wait for a stable release before you put a production system on it. The roadmap says what each phase has to prove before the next one starts.

Why would a company trust a new language?+

It shouldn't take it on faith, so Kavach is built to be checked. There is a written spec, and its rules are checked by conformance tests that run in the interpreter and in native code. Every example on this site runs against the real compiler when the site is built, and claims link to the file and line that back them.

Adopting it doesn't need trust up front either. An agent can start in observe mode, where its limits only report and never block, then move to suggest, where a person approves each action, and only then to enforce. And you can start with one agent or one module, not a whole codebase. See Agent Modes.

What happens if the project stops?+

That's a fair worry with any young language. Kavach is open source under the MIT and Apache 2.0 licenses, so the code can't be taken away, and anyone can carry it on.

kavach build makes an ordinary native executable, and it runs without Kavach installed. Kavach code calls C and can be built as a library other languages call, so a part written in Kavach can be swapped out later, one part at a time.

Who is building it?+

Kavach is led by Mithlesh, who also writes this course. It's built in the open on GitHub: every design decision has a written record there, with the options that were turned down and why.

Compared with what you use now

How is it different from Python, Go, Rust or TypeScript?+

It compiles to native code with no garbage collector, like Rust or C++, but reads closer to Python or Go. Integers and list indexes are checked, so an overflow or a read past the end stops the program instead of quietly giving a wrong answer. A function that can fail says so in its type, and the caller has to handle it: there are no exceptions.

The real difference is the part none of them has: what code may touch is in its signature, and agents with limits, approvals, an audit log and typed AI calls are part of the language. If you know one of those languages, Coming From Another Language maps what you know onto Kavach.

Is it fast?+

In the like-for-like benchmarks, where Kavach and C++ run on the same number of cores, Kavach's native code is faster in 18 of 23. Each one comes with a single command to run it yourself, and the losses are shown next to the wins.

13 more aren't counted yet. Most used to compare Kavach on all cores with C++ on one, which says nothing about which language is faster, so they are being run again with both sides on the same cores. Their charts say so. See Benchmarks.

Do I have to rewrite my code to use it?+

No. Kavach calls C libraries directly, and a Kavach library can be called from Python, Node.js or Go. So you can write one part in Kavach, the fast part or the risky part, and leave the rest where it is. Calling Python from Kavach is planned, not built yet.

See Calling C and A Library for Any Language.

Why would I move from a language that already works?+

If your language works for you and you don't run AI agents, you probably shouldn't, at least not yet. Kavach is worth it when you need to show what code can and can't do: an agent that handles money or customer data, AI-written code you have to sign off on, or a service where a silent overflow would be a real bug.

Start with one of those, not with a rewrite.

Getting started

How do I try it?+

The quickest way is the playground, right in your browser. To install it, follow Install, then write your first program.

Today it runs on Windows 10 or 11 and on Linux, on 64-bit Intel or AMD processors. macOS and ARM come later.

Is it free?+

Yes. The compiler, the standard library and these docs are open source, under the MIT or the Apache 2.0 license, whichever you prefer.

What does the name mean?+

Kavach (कवच) is the Hindi word for armor. The keywords are English, and you don't need any Hindi to use it. The name is about what it does: it keeps code inside the limits you set.
