- **Rounds left held after a panic** (2026-11-07): a spawned task that panics inside a loop of sums that don't wait (spec 15.2) leaves its up to 3 rounds in the runtime's queue (`runtime/native/src/rt_gpu/later.rs`), holding their lists until the program ends. - **Builds under 0.2 s** ([decision 0024](../decisions/0024-pay-only-for-what-you-use.md)): a "hello world" `kavach build` takes about 0.26 s (2026-11-01, Windows, release compiler), of which linking is about 0.25 s: the linker reads the whole runtime archive (74 MB with thin LTO). Ideas: a smaller archive (no debug information, no bitcode), linking a prebuilt object of the runtime's core, or a linker that caches. `rust-lld` was no faster. Measured again 2026-11-09 (release compiler, the archive now 190 MB): Windows 0.74–0.77 s warm. Linux (WSL, on ext4) 0.39–0.46 s, of which GNU ld takes about 0.42 s; rustup's `lld` (`cc -B…/gcc-ld -fuse-ld=lld`) links the same in 0.14–0.17 s, but its program keeps twice the code (1.15 MB stripped against 0.58 MB, `-z start-stop-gc` and `--icf=all` change nothing), which would break the size budget. Why (2026-11-09, link maps of hello world, LLD 23.1): lld's code is smaller (`.text` 405 KB against 413), but it keeps the exception tables (`.gcc_except_table`) of 11,092 functions when only about 300 of those functions are in the program: 600 KB against GNU ld's 12 KB.
