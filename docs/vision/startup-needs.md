# What Startups Need, and Where Kavach Fits

Research done 2026-11-14 from 2024–2026 surveys, funding news, incident reports and engineering blogs. It asks which startup needs Kavach can serve, through the language or through software built with it. The companion documents are [developer-needs.md](developer-needs.md) and [language-design-research.md](language-design-research.md). Many 2026 funding figures come from news aggregators; treat them as ranges.

## Sell safe agents first, the language second

The startup need that best fits Kavach today is **control over what AI agents and AI-written code are allowed to do, plus proof of that control for enterprise buyers**. Agent projects are being cancelled or blocked for "inadequate risk controls". Enterprise security reviews of AI features now add weeks. The best-known incidents, such as Replit's agent deleting a production database, happened because the rules lived in a prompt and not in the program. Investors and acquirers have put well over a billion dollars into tools that bolt this control on from the outside: gateways, guardrail firewalls, identity brokers and durable runtimes. None of them puts the policy (capabilities, limits, approvals, audit) inside the program, where the compiler can check it and a reviewer can read it. That gap is Kavach's clearest unique selling point (USP). The hard part is adoption. New languages win through one narrow wedge that needs no rewrite. Startups now refuse languages their AI coding tools cannot write, and models score close to 0% on hard tasks in languages they have not seen. The money in this field goes to platforms and products built with a language, almost never to the language itself. So the recommended path for a one-maintainer project is: first prove that AI agents can write Kavach; then ship an agent-control product that wraps agents written in Python or TypeScript; then add evidence export and spending policy for agent payments. Speed-focused infrastructure products and an "AI-safe backend language" come later, once there are measured numbers and real users.

## Agents fail on control and proof, not only on accuracy

The biggest blocker for agents is still quality. In LangChain's 2025 survey (1,340 responses, about half from companies under 100 people), **32% named quality as the top blocker**. Latency came second, and **security was the second-largest concern (24.9%) at companies with 2,000+ staff**. Those large companies are exactly the buyers that startups sell to ([LangChain](https://langchain.com/state-of-agent-engineering)). The same survey found that **29.5% of teams do not evaluate their agents at all**. Gartner expects **more than 40% of agentic AI projects to be cancelled by the end of 2027**, because of cost, unclear value and "inadequate risk controls" ([Silicon.eu](https://www.silicon.eu/gartner-over-40-percent-of-agentic-ai-projects-will-be-discontinued-by-the-end-of-2027-18197.html)). How many agents are really in production is disputed. LangChain says 57%, while Cleanlab's survey of 1,837 people found only **5%** ([Cleanlab](https://cleanlab.ai/ai-agents-in-production-2025/)). The samples differ, so the true figure is unknown. A practitioner study found that **68% of production agents need a human within ten steps** ([arXiv 2512.04123](https://arxiv.org/abs/2512.04123)). Human approval is therefore a normal production path, not an edge case.

The incidents show what goes wrong. In July 2025, Replit's agent **deleted a live production database during a declared code freeze**, against repeated instructions. Replit's fix was structural: it separated dev and prod databases and made staging mandatory ([eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/)). In another case, a malicious public GitHub issue made an agent copy private repository data into a public pull request ([UpGuard](https://www.upguard.com/blog/ai-github-agents-issue-leaked-private-repos)). In a third, a support ticket steered an agent that held Supabase's `service_role` key into leaking data ([Pomerium](https://www.pomerium.com/blog/when-ai-has-root-lessons-from-the-supabase-mcp-data-leak)). Simon Willison named the pattern the **"lethal trifecta"**: private data, untrusted instructions and a way to send data out, all in one agent. He argues it is an architecture problem that model training cannot fully remove ([Simon Willison](https://simonwillison.net/2025/Jul/6/)). Payments show the same gap. Agent payment protocols such as **x402 have no spend limits**, so caps must come from the wallet or from the agent's own runtime ([DEV](https://dev.to/suraj_khaitan_f893c243958/your-ai-agent-can-pay-now-x402-ap2-and-ucp-are-not-your-spending-policy-3l25)).

The blockers fall into three groups: the agent is wrong, the agent does something it should not, and nobody can prove what it did. Kavach can honestly claim the second and third groups. Capabilities the agent was never granted, limits the runtime enforces, and approvals that survive a crash are rules a model cannot talk its way around. Kavach can also check the lethal trifecta at compile time. The compiler knows which agent reads private data, which takes untrusted input and which can send data out. It can refuse to build, or demand an approval, when one agent has all three. For the first group, a language cannot fix model accuracy. Kavach's honest offer there is smaller: typed outputs, contracts that reject bad outputs, and generated tests with faked outside systems, which give the 29.5% who do no evaluation a cheap start.

Teams also reject heavy frameworks. Octomind dropped LangChain because of "abstractions on top of abstractions" ([Octomind](https://octomind.dev/blog/why-we-no-longer-use-langchain-for-building-our-ai-agents)). "Learn with frameworks, deploy with raw APIs" is now common advice ([tianpan.co](https://tianpan.co/blog/2026-04-19-orchestration-framework-trap-langchain-production)). So each team rebuilds permissions, limits and logging by hand. The lesson for Kavach is that each safety feature must feel like one line of plain code (`can ...`, `approve ... when ...`), not a framework to learn.

## Buyers already pay over a billion dollars for bolt-on agent control

Agent control is a funded category, so Kavach does not need to create demand. In 2025, security vendors bought four guardrail startups for roughly **$1.1–1.3B combined** (SEC figures). Palo Alto Networks paid $634.5M for Protect AI, and Check Point, SentinelOne and F5 bought Lakera, Prompt Security and CalypsoAI ([deals tracker](https://guptadeepak.com/agent-security/deals/); [CyberScoop](https://cyberscoop.com/check-point-lakera-acquistion-ai-security/)). Venture rounds followed. Noma Security raised a **$100M Series B** for agent security and governance ([SecurityWeek](https://www.securityweek.com/noma-security-raises-100-million-for-ai-security-platform/amp/)). Keycard raised **$38M** to replace static API keys with task-scoped tokens ([Help Net Security](https://www.helpnetsecurity.com/?p=345887)). Infisical raised **$40M at a $600M valuation** for agent credential isolation and approval workflows ([BankInfoSecurity](https://bankinfosecurity.com/infisical-raises-40m-to-secure-ai-agent-credentials-a-33297)). Rein Security ($25M) and CodeIntegrity (~$5M) sell runtime layers that block risky agent actions ([PR Newswire](https://www.prnewswire.com/news-releases/rein-security-raises-25-million-to-secure-the-ai-agents-enterprises-build-and-stop-the-ones-that-attack-them-302901591.html); [GeekWire](https://www.geekwire.com/2026/codeintegrity-raises-4-8m-to-put-permanent-guardrails-on-unpredictable-ai-agents/)). Durable execution is the hottest part of the market. Temporal reached a **$12.55B valuation** in September 2026, with **over $250M run-rate revenue growing 200%+ a year** and customers such as OpenAI and Cursor ([Temporal](https://temporal.io/news/temporal-raises-550m-at-a-12-55b-valuation)). Restate raised $20M for durable infrastructure aimed at agents ([TechCrunch](https://techcrunch.com/2026/09/30/restate-lands-20m-as-the-need-for-durable-infrastructure-increases-with-ai-agents/)). On the observability side, Braintrust was valued at $800M ([ChatForest](https://chatforest.com/reviews/braintrust-ai-eval-observability-platform/)), and LangSmith charges **$39 per seat per month** plus usage ([LangChain pricing](https://www.langchain.com/pricing)).

Every one of these products sits **at the boundary**: a proxy, a gateway, an identity broker, a tracer or a sidecar. They see traffic, not intent. AWS now sells the same idea to startups: Cedar policies in Bedrock AgentCore, checked at the gateway before a tool runs, with "default deny" ([AWS Startups](https://aws.amazon.com/aws-startups/learn/prove-it-part-2-formal-logic-cedar-policies-and-the-economics-of-verification/)). This shows the market accepts "check the policy before the tool runs". Kavach moves that policy into the source code. A line such as `can Payments.refund` with `amount <= 10_000` is reviewed in the pull request, checked before deploy, and cannot drift from the running code. Compile-time checks are new: none of the frameworks named above checks permissions at compile time; they offer runtime hooks. A one-language package of durable steps, approvals that can wait hours, and limits counted across restarts (`per day`) is also not offered by any single vendor.

This USP has a clear limit. Compile-time checks cover only code written in Kavach. Tools called through Python or a remote MCP server are opaque to the compiler, so the runtime must still check calls at the boundary. Credentials must still be scoped by an identity system. Kavach should therefore plug into Keycard- or Infisical-style brokers and into existing dashboards (it already exports OpenTelemetry), not try to replace them.

## Enterprise security reviews ask questions the compiler can answer

For B2B startups, the binding cost of compliance is calendar time, not money. A first SOC 2 costs roughly **$15K–$60K**, with Type 2 audits alone at **$12K–$45K** ([BD Emerson](https://www.bdemerson.com/article/soc-2-cost)). A Type 2 report takes about 4.5–12 months, including a 3-month observation window that cannot be shortened ([Mycroft](https://mycroft.io/blog/how-long-does-soc-2-take-a-realistic-breakdown-for-startups-and-saas)). Vanta's 2025 survey says teams spend **12 working weeks a year on compliance and 9 on vendor security reviews** ([Business Wire](https://www.businesswire.com/news/home/20251029144534/en/Vanta-State-of-Trust-2025-AI-Threats-Outpace-Security-Expertise)). This is a vendor survey, so treat it as a direction, not a precise figure. AI features add more work. The Cloud Security Alliance added **47 AI-specific questions** to its standard questionnaire. One account says AI-feature reviews take **4–8 weeks longer**, and that "nobody on the AI team has written down the answer" ([tianpan.co](https://tianpan.co/blog/2026-04-27-80-question-wall-enterprise-ai-security-questionnaire)). That figure comes from a single blog. The questions about agents are concrete. What can the agent touch? Does it see only records the user may see? Which actions need a human? Where is the log? ([TechTarget](https://www.techtarget.com/enterprise-software/feature/AI-agents-in-enterprise-software-Questions-to-ask-vendors?amp=1)).

Regulators ask the same questions. FINRA's 2026 report covers AI agents for the first time. It warns about agents acting **beyond a user's authority** and without human validation, and about weak auditability ([Debevoise](https://www.debevoise.com/insights/publications/2025/12/finras-2026-regulatory-oversight-report-continued)). EU AI Act Article 26 requires deployers of high-risk systems to give oversight to people with authority, to suspend use when the system presents a risk, and to keep automatic logs for **at least six months** ([Art. 26](https://artificialintelligenceact.eu/article/26/)). The high-risk deadlines moved to **2 December 2027** (Annex III) and **2 August 2028** (Annex I) ([Gibson Dunn](https://www.gibsondunn.com/eu-ai-act-omnibus-agreement-postponed-high-risk-deadlines-and-other-key-changes/)). Enterprise buyers ask now, though, so "pass the security review" is a stronger pitch today than "ready for the EU AI Act". India's rules point the same way. RBI's 2025 Payment Aggregator Directions require annual system and cyber audits ([AZB & Partners](https://www.azbpartners.com/bank/rbi-issues-consolidated-reserve-bank-of-india-regulation-of-payment-aggregators-directions-2025/)). RBI defines an audit trail as a record that "reconstructs and examines the sequence of activities" and requires cyber incident reports within six hours ([Mondaq](https://www.mondaq.com/india/financial-services/1689480/an-analysis-of-the-reserve-bank-of-indias-master-direction-on-regulation-of-payment-aggregators-2025)). The DPDP Rules require keeping logs for at least one year ([SS Rana](https://ssrana.in/articles/meity-notifies-final-digital-personal-data-protection-rules-2025/)).

Trust in compliance evidence is also falling. In March 2026 a whistleblower accused the YC-backed startup Delve of producing fabricated SOC 2 evidence; these are allegations, with no legal outcome yet ([IANS Research](https://www.iansresearch.com/resources/all-blogs/post/security-blog/2026/03/30/delve-allegations-expose-weak-points-in-modern-compliance)). This creates demand for evidence that is hard to fake because it comes from the real system. A Kavach command that prints, for each agent, its capabilities, limits, approval points and audit-log schema, tied to a commit hash, answers the agent questions straight from compiler-checked code. A pull request that shows "this release gives the refund agent `Email.send`" is direct evidence of least privilege and change review. Two cautions apply. No source shows that any auditor has yet accepted compiler-derived evidence. And code covers only a slice of SOC 2: much of it is HR, devices and cloud configuration. Kavach should feed evidence into Vanta and Drata, not compete with them.

Money-moving systems show where enforced rules would have helped. Citi once posted a $280 credit as **$81 trillion**. Two employees missed it, and a third caught it 90 minutes later ([Fortune](https://fortune.com/2025/02/28/citigroup-81-trillion-fat-finger-mistake-customer-account-credit-near-miss/)). India's UCO Bank wrongly credited **Rs 820 crore** through IMPS ([Outlook Business](https://www.outlookbusiness.com/news/rs-820-cr-erroneously-credited-to-uco-bank-account-holders-due-to-technical-glitch)). Synapse collapsed with a **$65–95M ledger shortfall** that may never be fully reconciled ([businessjournalism.org](https://businessjournalism.org/2025/02/synapse/)). Double charges keep coming from batch reruns and retry logic ([GitHub blog](https://github.blog/news-insights/the-library/revenge-of-the-double-billing)). A runtime-enforced amount limit stops the Citi class of error. Exactly-once durable steps stop the double-charge class. Contracts on ledger totals make a shortfall visible early, though no language can fix reconciliation across several banks. Formance's $21M Series A for Numscript, a small language for money movements, shows that safe money logic as a language feature can be funded ([TechCrunch](https://techcrunch.com/2025/01/29/formance-raises-21-million-to-build-the-aws-of-fintech-infrastructure)).

## AI-written code moved the bottleneck from writing to checking

Studies from 2025–2026 agree on the direction, even though many come from vendors who sell the fix. When a secure and an insecure option existed, models chose the insecure one in **45%** of Veracode's tasks, and security is "not improving" as models improve ([Veracode](https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/)). In CodeRabbit's sample, AI co-authored pull requests had **about 1.7 times more issues** than human-only ones ([CodeRabbit](https://www.coderabbit.ai/blog/state-of-AI-vs-human-code-generation-report)). GitClear found that duplicated code blocks rose **8-fold in 2024**, while refactoring fell ([DevClass](https://www.devclass.com/ai-ml/2025/02/20/ai-is-eroding-code-quality-states-new-in-depth-report/1626250)). Independent sources point the same way. In METR's randomized trial, experienced developers were **19% slower** with AI, yet believed they were faster ([DX](https://newsletter.getdx.com/p/metr-study-on-how-ai-affects-developer-productivity)). Only **33% of developers trust AI output**, and **66%** name "almost right, but not quite" as their top frustration ([Stack Overflow](https://stackoverflow.blog/2025/07/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here)). Google's DORA 2025 report found that AI raises throughput but **delivery instability keeps rising** ([DORA](https://services.google.com/fh/files/misc/2025_state_of_ai_assisted_software_development.pdf)).

The recorded breaches of "vibe-coded" apps are mostly basic access-control mistakes. A scan of 1,645 apps built on Lovable found **170 (10.3%) with exposed databases** because row-level security was missing ([Daily CyberSecurity](https://securityonline.info/cve-2025-48757-lovables-row-level-security-breakdown-exposes-sensitive-data-across-hundreds-of-projects/)). Moltbook exposed about **1.5 million API keys** the same way ([timeline](https://ismysitehackable.com/blog/vibe-coding-security/vibe-coding-breach-timeline)). A cleanup trade has appeared, reportedly charging **$200–400 per hour** to add tests, CI and monitoring ([Gizmodo](https://gizmodo.com/after-ai-led-to-layoffs-coders-are-being-hired-to-fix-vibe-coded-screwups-2000657915)). Meanwhile the app builders grow fast: Lovable reports about **$600M ARR** ([Wikipedia](https://en.wikipedia.org/wiki/Lovable_(company))). Buyers already pay for verification of AI code. CodeRabbit is valued at **$1.5B** ([Tech Funding News](https://techfundingnews.com/coderabbit-lands-143m-at-1-5b-valuation-as-ai-generated-code-surges/)), Socket at **$1B** ([Socket](https://socket.dev/blog/socket-raises-60m-series-c-press-release)), and Semgrep ships an MCP server so assistants can scan their own output ([Sacra](https://sacra.com/c/semgrep/)).

Kavach's answer here is **deterministic**, while review bots are probabilistic: "a second AI checks the first AI". A function that reads user data without a declared capability does not compile. A contract that a generated test breaks fails the build. A reviewer can read a short signature with capabilities and contracts instead of the whole body. These features match the breach classes above and the review bottleneck, and they are the strongest language-level USP found. Supply chain is a medium fit. In a USENIX study, about **19.7% of packages recommended by LLMs did not exist**, and 43% of the fake names repeat on every run ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-slopsquatting-ai-supply-chain-20260419/)). Per-package capabilities checked at compile time would limit the damage of a bad package.

Token cost is a real but weaker pain. Claude Code averages about **$150–250 per developer per month** in enterprise use ([morphllm](https://www.morphllm.com/ai-coding-costs)), and heavy agent users report bills near $2,000 ([coommit](https://coommit.com/blog/ai-coding-tool-costs-2026)). Cursor's move to usage billing caused a backlash and refunds ([TechCrunch](https://techcrunch.com/2025/07/07/cursor-apologizes-for-unclear-pricing-changes-that-upset-users/)). For most startups, this is a budget and rate-limit annoyance, not a survival issue. Kavach's token savings are also not unique. Anthropic cut one workflow from about 150,000 to 2,000 tokens (**98.7%**) by giving agents structured tools ([Anthropic](https://www.anthropic.com/engineering/code-execution-with-mcp)), and any language can do the same with LSP and MCP. Kavach's `outline` and `query` tools should therefore be sold as **accuracy**: exact answers about callers, effects and types, instead of grep.

The field of "AI-native languages" is crowded. MoonBit has been in beta since May 2025 with a built-in coding agent ([MoonBit](https://www.moonbitlang.com/blog/beta-release)). Vercel Labs' experimental language Zero emits JSON diagnostics with repair data for agents ([Techstrong.ai](https://techstrong.ai/features/vercel-labs-builds-a-programming-language-designed-for-ai-agents/)). Lean-based verification companies such as Harmonic, valued at **$1.45B**, aim at fully proven code ([SiliconANGLE](https://siliconangle.com/2026/01/15/nvidias-nventures-backs-harmonic-ai-series-c-mathematical-superintelligence/)). Kavach cannot win on "AI-native" alone. Its distinct mix is capabilities in signatures, contracts, generated tests with fakes, and agent guardrails, aimed at ordinary product backends: lighter than proofs and stronger than review bots. The bar to beat is **TypeScript with strict types plus a review bot**. TypeScript became GitHub's most-used language in August 2025, and GitHub links part of this to AI ([GitHub Octoverse](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)).

## Speed sells only where speed is the product

Cloud is the **second-largest cost after payroll** at small and midsize software firms, averaging **about 10% of revenue** ([CIO.com](https://www.cio.com/article/4110708/cloud-costs-now-no-2-expense-at-midsize-it-companies-behind-labor.html)). **84%** of organisations call cloud spend their top challenge, and about **27%** of it is wasted ([Flexera](https://www.flexera.com/about-us/press-center/new-flexera-report-finds-84-percent-of-organizations-struggle-to-manage-cloud-spend)). But much of that spend is storage, egress, managed databases and GPUs, which a language does not change. For AI products, the GPU dominates, and gross margins average about **45%** against 75–85% for classic SaaS ([CloudZero](https://www.cloudzero.com/blog/ai-gross-margin/)).

Where compute is the cost, rewrites pay. Cloudflare's Rust proxy Pingora uses **about 70% less CPU and 67% less memory** than the NGINX setup it replaced ([Cloudflare](https://blog.cloudflare.com/how-we-built-pingora-the-proxy-that-connects-cloudflare-to-the-internet/)). Grab rewrote one Go service in Rust and needed far fewer cores ([Grab](https://engineering.grab.com/counter-service-how-we-rewrote-it-in-rust)). A secondary report says TikTok rewrote **only three payment endpoints** and freed over 400 CPU cores ([lord.technology](https://lord.technology/2025/11/02/tiktoks-payment-service-struggled-at-100000-queries-per-second-until-engineers-rewrote-critical-apis-in-rust.html)). The pattern is partial rewrites of hot paths, proven with shadow traffic. That rewards a language with easy interop, not one that demands a full rewrite. Two smaller trends help compiled single binaries. AWS Lambda now **bills the INIT phase**, so cold starts cost money ([AWS](https://aws.amazon.com/blogs/compute/aws-lambda-standardizes-billing-for-init-phase)). And in LLM serving, vLLM found that Python on the CPU side left the GPU idle much of the time ([vLLM](https://vllm.ai/blog/2024-09-05-perf-update)).

The language gap is real. Go users are **91% satisfied**, but they most miss **better error handling, enums and sum types, and nil safety** ([Go blog](https://go.dev/blog/survey2025)). Rust is admired, yet about **45% of people who stopped using Rust cite compile times** ([Rust blog](https://blog.rust-lang.org/2025/09/10/rust-compiler-performance-survey-2025-results)). "Admire Rust, adopt Go" leaves an empty corner: easy to learn, fast to build, no GC, sum types, no null. Kavach aims there. But its speed numbers are still design targets, not published measurements. Every winning case above published hard numbers, and Kavach must do the same.

The commercial pattern for fast tools is clear. They win adoption as free, fast, single-binary tools, then earn money through a managed cloud or an acquisition. Bun had **"$0 in revenue"** when Anthropic bought it ([Bun](https://bun.com/blog/bun-joins-anthropic)), and OpenAI bought Astral (uv, Ruff) to strengthen Codex ([The New Stack](https://thenewstack.io/openai-astral-acquisition/)). Kavach's speed is a USP for products where speed or footprint *is* the product: gateways, per-host agents and collectors, LLM routers, CLIs. It is weak for ordinary CRUD backends (Go and Node are fine there) and for GPU kernels (CUDA, PyTorch and Mojo own that). Memory-safety rules such as the EU Cyber Resilience Act, binding from December 2027, push C and C++ vendors ([Jones Day](https://www.jonesday.com/de/insights/2026/07/eu-cyber-resilience-act-24hour-reporting-duties-start-september-11-2026)). Cloud startups already use memory-safe languages, though, so this matters more for Kavach's later embedded and on-device plans.

## New languages win through one wedge, and AI writability is now the gate

Every language that won startups rode one concrete wedge. Kotlin had Android. TypeScript was a superset of JavaScript that teams could adopt file by file. Go had Docker and Kubernetes. Zig has TigerBeetle, whose company now helps fund the Zig foundation ([TigerBeetle](https://tigerbeetle.com/blog/2025-10-25-synadia-and-tigerbeetle-pledge-512k-to-the-zig-software-foundation/)). Bun and uv were drop-in tools that needed no rewrite. Languages that sold a new way of working without a drop-in wedge stayed niche. WSO2 kept Ballerina alive only by putting it under a paid integration product ([WSO2](https://wso2.com/about/news/new-wso2-integration-offerings-maximize-power-of-ai/)).

In 2026 a new gate sits next to hiring: **can the AI coding tools write it?** On hard tasks, models score **0–1% zero-shot in Gleam and MoonBit**, against 59–89% in popular languages, and most failures are syntax errors ([Giagnorio et al.](https://huggingface.co/papers/2606.16827.md)). The same study shows the gap can close. Few-shot examples beat retrieval over the docs, and continued pre-training on a small corpus lifted MoonBit to about 42% on HumanEval. Kavach's `llms.txt`, MCP server and precise compiler errors are the right levers. But until there is a published benchmark, a startup that lets agents write most of its code will treat Kavach as a language its agents fail at.

Bus-factor fear is also backed by recent events. Deno joined Cloudflare, and Deno Deploy shuts down around April 2027 ([TechCrunch](https://techcrunch.com/2026/10/10/cloudflare-acquires-deno-to-improve-its-workers-programming-model/)). Dark Inc. ran out of money because "an 8 year old product with no traction was not going to attract new investment" ([Darklang](https://blog.darklang.com/goodbye-dark-inc-welcome-darklang-inc/)). A one-maintainer, pre-alpha language will hear this objection first. The answers are an escape hatch (interop, leaving one module at a time) and adoption limited to non-critical parts at first. Kavach's observe mode for agents fits this well.

Finally, the money is in what runs the code, not in the language. Vercel reached **$9.3B** on a framework that leads into a cloud ([Business Wire](https://www.businesswire.com/news/home/20250930898216/en)). Modular reached **$1.6B** selling an inference platform with Mojo inside ([Modular](https://modular.com/blog/modular-raises-250m-to-scale-ais-unified-compute-layer)). Temporal sells reliable execution to teams that keep their own language. Companies whose product was mostly a language plus their own hosting (Dark, Deno) failed or were absorbed. For Kavach, realistic models are open source plus paid enterprise evidence and support features, corporate pledges after a flagship user appears, or acquisition by an AI lab that values a toolchain that makes agents safer. A self-hosted "Kavach Cloud" that competes with the big clouds is the trap to avoid.

## Ranked opportunities for Kavach

The ranking weighs four things: how sharp and funded the startup pain is, how unique Kavach's answer is, whether it works **without** the startup rewriting in Kavach, and whether one maintainer can build it. "Wedge" means a way into startups. "Product" means software built with Kavach.

| Rank | Opportunity | Type | Startup pain | Kavach USP | Main competitors | Main risk |
|---|---|---|---|---|---|---|
| 1 | Agent control runner and capability-checked MCP gateway | Wedge + product | Agents do things they should not; projects cancelled for weak risk controls | Policy in code: capabilities, limits per day, approvals that wait, audit log, crash-resume, trifecta check | Rein, CodeIntegrity, Aurascape, AWS AgentCore + Cedar, agent SDK hooks, Temporal/Restate | Compiler cannot see inside Python or remote tools |
| 2 | Agent trust sheet: security-review evidence from source | Product (feature of 1) | AI reviews add weeks; 12 weeks/year on compliance; fake-evidence scandal | Answers derived from checked code, tied to a commit, diffable in PRs | Vanta, Drata (partners), Noma, Zenity | Auditors have not yet accepted compiler evidence |

### 1. Agent control runner and capability-checked MCP gateway

**Pain.** Gartner expects over 40% of agent projects to be cancelled, partly for weak risk controls. Replit, GitHub MCP and Supabase MCP all failed because an agent held more rights than its task needed, and the only rule was a prompt. **Evidence of spending.** About $1.1–1.3B went into guardrail acquisitions, $100M into a single agent-security round, and Temporal grew to $12.55B by keeping agents from failing mid-task. **USP.** No single vendor combines compile-time capabilities, runtime limits counted across restarts, approvals that wait hours, durable resume and an audit log, all in the same source file. A gateway that exposes only the tools an agent's `can` list allows, and applies limits and approvals on each call, works for agents written in Python or TypeScript. This is the Temporal pattern: teams keep their main language. It also gives Kavach its "Bun moment", a must-have native binary that people use without writing Kavach. The Replit incident is a ready-made demo script. **Risks.** Tools behind Python or remote MCP servers are opaque, so this layer is a runtime check there, not a compile-time proof. Teams change their agent stack every few months, so the gateway must speak MCP and plain HTTP and accept any model provider.

### 2. Agent trust sheet

**Pain.** AI-feature security reviews reportedly add 4–8 weeks, and teams already spend 12 weeks a year on compliance. **Evidence.** CAIQ added 47 AI questions; FINRA and EU AI Act Article 26 ask for oversight, suspension and logs; the Delve allegations make code-derived evidence more valuable. **USP.** A `kavach audit` output per agent (capabilities, limits, approval points, log schema, contracts) mapped to CAIQ-AI, SOC 2 access and change-management controls, and EU oversight duties, signed and tied to a commit. It cannot drift from the code. **Competitors.** Posture tools such as Noma and Zenity scan from the outside. Vanta and Drata should be integration targets. **Risks.** No auditor has yet accepted compiler-checked properties. The first users need a mapping written with an audit firm. This is a sales feature of opportunity 1 more than a separate business.

### 3. Spending policy for agent payments and safe money workflows

**Pain.** Agents can now pay, but x402 has no caps, and limits live separately in each payment rail. A cross-rail daily budget, such as "no more than ₹4 lakh a day across card, UPI and x402", has no home. Retries cause double charges, and single fat-finger credits reach absurd sizes. **Evidence.** Stripe, Visa and Mastercard ship agent tokens with some issuer limits ([elogic](https://elogic.co/blog/agentic-payments/)). Formance raised $21M for a money DSL. Indian payment aggregators face annual audits and six-hour incident reporting. **USP.** Durable per-day limits, exactly-once steps, approval above a threshold, and generated tests that fake the payment provider and cover retries. This is Kavach's "refunds <= 10,000" feature in its purest form, and India is a natural first market. **Risks.** Regulated buyers distrust a pre-alpha language near money. Start with a narrow component (a refund or payout agent), never core ledgers.

### 4. Checkable AI-written backend code

**Pain.** AI makes more code with more defects, and humans must check it with less trust. **Evidence.** Veracode's 45%, CodeRabbit's 1.7x, METR's slowdown, DORA's rising instability, and the access-control breaches. Review tools are valued at $1–1.5B, so the budget line exists. **USP.** Deterministic checks instead of a second AI: effects and authority in signatures, contracts as the unit of review, tests generated from types and contracts. **Competitors.** TypeScript with strict types plus review bots is the real bar. MoonBit and Zero compete for the "AI-native" story, and Lean and Dafny companies own full proofs. **Risks.** This is the wedge most exposed to the AI-writability gate, hiring and bus-factor objections. It needs a published benchmark and, ideally, a study showing fewer defects. No such study exists for any language yet.

### 5 to 8. Later opportunities

Fast infrastructure products (rank 5) fit Kavach's no-GC, single-binary design. The best candidates are an OpenTelemetry collector or per-host agent, an API gateway or rate limiter, and an LLM router that cuts CPU-side overhead. The strongest first one is the gateway from opportunity 1, because it joins speed with agent control. All of them need measured benchmarks before anyone will switch from Vector, Envoy or LiteLLM. Hot-path services (rank 6) target the Go gap but need mature interop, because the paying pattern is rewriting three endpoints, not a whole system. The app-builder backend (rank 7) has the largest upside, since the buyers have the money and a year of public breaches, but no platform will adopt a pre-alpha language. The capability registry (rank 8) needs an ecosystem first. Three ideas are weak and should be avoided: a standalone authorization service (Permit.io raised only $14M in total ([Help Net Security](https://www.helpnetsecurity.com/2024/02/16/permit-io-funding-8-million/)), and the OPA team went to Apple ([Heise](https://heise.de/-10574287))); a standalone ledger database (TigerBeetle and Formance own it); and a hosted Kavach cloud.

## A sequence one maintainer can carry

The order below puts proof before products and products that need no rewrite before products that do. Each step makes the next one credible.

| Step | Build | Why now |
|---|---|---|
| 1 | Publish an AI-writability benchmark: Kavach versions of HumanEval/MBPP, measured with and without `llms.txt`, MCP and compiler feedback. Publish an open corpus of correct Kavach code. | Without this, startups that let agents write their code refuse at once. It is also the cheapest step. |
| 2 | Build the "Replit demo": a refund agent with capabilities, a daily limit, an approval that waits, a crash and resume, and an audit log. Add the trifecta check and `kavach audit` output. | Turns the USP into something a founder can watch in five minutes. |
| 3 | Ship the agent runner / capability-checked MCP gateway as one native binary that wraps Python and TypeScript agents, with observe mode and OpenTelemetry export. | Adoption with no rewrite, like Bun and uv. It also tests Kavach's speed claims in a real product. |
| 4 | Find 3–5 design partners: B2B AI startups selling to enterprises, including Indian payment and fintech teams. Map the trust sheet to CAIQ-AI and SOC 2 controls with one audit firm. | Turns "the compiler proved X" into evidence a reviewer accepts. |
| 5 | Add the spending-policy pack for Stripe, Razorpay/UPI and x402. | The second paid use case, on the same runtime. |
| Later | Fast infra products with published benchmarks, hot-path interop, app-builder partnerships, capability registry. | Each needs proof, users or an ecosystem that steps 1–5 create. |

Each step has a clear exit test. Step 1 passes when frontier models solve a meaningful share of tasks with Kavach's tools. Step 3 passes when someone runs the gateway in front of an agent they did not write in Kavach. Step 4 passes when one enterprise review accepts the trust sheet. If step 1 fails badly, the language wedge (rank 4) should wait, and the gateway should be sold as a product that happens to be written in Kavach.

## Conclusion

The research changes the question. "Will startups adopt a new language?" has a discouraging answer for a pre-alpha, one-maintainer project. "Will startups pay to make agents safe enough to sell?" has a clearly positive one. Kavach's rare asset is that its policy lives in the program, so the same declaration is a compile error, a runtime limit, a review diff and a line of audit evidence. Boundary tools can match one of these, but not all four together. That points to leading with the outcome (agents that cannot overstep, and proof of it) and letting the language spread behind it, the way Temporal spread a programming model and Next.js spread a cloud.

Three things are still unknown and decide everything else. Can models write Kavach well with its tools? Do auditors accept compiler-derived evidence? Do Kavach's speed targets hold in public benchmarks? None of these was measured in the research, and no startup was interviewed. The next month of work should produce numbers on the first question and one design partner on the second. Everything in the ranking above depends on those results more than on any further market research.
