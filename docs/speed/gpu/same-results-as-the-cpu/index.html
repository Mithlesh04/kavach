GPU: Same results as the CPU

● Advanced4 min

The GPU gives the CPU's answers: overflow still panics with the same message, and + - * give the same bits.

In simple terms

The GPU must give the same answers as the CPU, like two calculators that agree. A number that grows too big is still stopped with the same message; only a few kinds of maths on decimals may differ by a tiny amount, in the very last binary digit.

  • Whole-number arithmetic is checked on the GPU too: overflow and division by zero panic with the CPU's message, naming the same line inside the gpu fn. When several items fail, the GPU may report a different one first.
  • +, - and * on Float32 give the same bits, unless the GPU fuses a multiply with an add (one rounding instead of two).
  • /, %, **, math.pow and math.sqrt may differ in the last bits, as GPUs are allowed to; floor, ceil and round are exact.

When a panic shows

A map whose list stays in GPU memory doesn't wait for the GPU to finish, so a loop of them runs back to back. Here the last item overflows. On the CPU the panic stops the loop; on the GPU, looped prints first:

  • The panic shows the next time the program reads the list on the CPU (ns[0] here), when another GPU call waits for its own result, or when the program ends.
  • Its message and line are the same either way. Only when it shows changes: code after the map may have run by then.
  • To find where a panic starts, run with KAVACH_GPU=off.
