## Open questions

- Fine-grained built-in capabilities beyond files, e.g. `Net("api.stripe.com")`.
- A folder that comes from a value (`uses Fs(config.dir)`), not only written text.
- How events reach agents in production: HTTP, queues, schedules. Probably a `std.ai` server helper.
- Where approval requests are delivered (webhook, Slack, email) and the timeout setting.
- Providers other than Anthropic, fallbacks, prices and `ai.ask_full` are in 8.4; money budgets in `limit Ai` in 8.3 ([decision 0140](../../decisions/0140-ai-providers.md)).
- Fallbacks (8.4), where decision 0140 is silent, for a maintainer's review: `BadRequest`, `CutOff`, `InvalidOutput`, `NoKey` and `Failed` don't move on; when every model fails, the error is the last try's; an answer that isn't a valid `T` is asked for again from the start of the list; the call counts once for `count`, with the largest `max_tokens` in the list for `UnderWay.Largest`; the audit log's line for a model moved on from names the error's variant, not its message.
- Prices, costs and money budgets (8.3, 8.4, 8.6), where decision 0140 is silent, for a maintainer's review: a program gives its own prices by wrapping its provider, as the decision's example does, with nothing new to learn; `price` is worked out when the program is built, as `check` is, so a built program keeps the prices of its build; Anthropic's table has only the four models whose names the pricing page gives, and `claude-haiku-5-5` at its price for prompts up to 100,000 tokens (a longer prompt costs five times as much, so its estimate is low); cache writes are counted at the `input` price, though Anthropic bills them at 1.25 or 2 times it; `a.model` is the model's name, not its `Model`; a usage count is the sum of the tries that gave it, `none` when none did; an `ask` that reached a model counts in `ai.spent` whether it answered or failed, and one with no known cost goes into `unpriced`; `ai.spent` needs no capability; `cost <=` refuses an `ask` whose list has any model with no price, even when an earlier one would answer; a rule can't read both `tokens` and `cost`; a cost the reply gave no counts for counts as 0 in a limit; the refusal of a `cost` limit gives the window's cost so far.
- Counting a prompt's tokens before sending (`ai.count`, 8.3, 8.4, 8.6), where decision 0140 is silent, for a maintainer's review: it is written as `ask` is, with the same model rules, and a list of models counts with its first model; it counts the prompt and `instructions`, not the type `ask<T>` writes in; `read_count` takes the call, as `read` does, and a reply with no count goes to `read` to say what went wrong; a counting call that fails is an error, with no fall back to the estimate; counting calls have a gate of their own for each provider and key; `limit Ai`'s rules (`count` too) and `approve` don't apply to a count, which adds nothing to `ai.spent` and isn't journaled; `Anthropic()`'s count leaves out `max_tokens`, `stop_sequences` and `extra`, and its estimate is one token for every 4 characters; a dry run's count is 0, marked as not counted.
- Signing AWS requests (`Auth.AwsSignature`, 8.4), where decision 0140 is silent, for a maintainer's review: credentials come only from `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`, not AWS's files, profiles or roles; a variable set to empty text counts as not set; the `Model`'s `api_key_env` and the provider's `key_variable` decide nothing, so a program can't use two AWS accounts at once; the signed headers are `host`, `x-amz-date`, `x-amz-security-token` and every header the provider wrote, with no `x-amz-content-sha256` header; the path is percent-encoded once more as for every service but S3, and not normalized (no `.` or `..` taken out), so S3 is not served; the machine's clock is used as it is, with no correction for skew; `service` and `region` are letters, digits and `-`; the gate's key is the provider's type and `AWS_ACCESS_KEY_ID`; a request's `host` header now has its port when it is not the scheme's own.
- `held <= n` in `limit` (8.3), for a maintainer's review: a call holds its place while it runs, and one past the limit is refused with `Denied`, as other limits refuse. Not decided: waiting for a place instead of being refused, and a place held after the call returns, until a value it gave back (a licence, a connection) is let go.
- Google access tokens (`Auth.GoogleToken`, 8.4), where decision 0140 is silent, for a maintainer's review: only a service account's JSON key file is read, from `GOOGLE_APPLICATION_CREDENTIALS` or the variable the `Model`'s `api_key_env` names, never `gcloud`'s default file, the metadata server or other kinds of credentials; a key file that can't be used is `BadKey`; the token server must be `https://`, or `http://` on this machine; `KAVACH_AI_URL` doesn't move the token server; a token is kept until 5 minutes before it ends, and one without `expires_in` is used once; a token the provider then refuses (401) is still kept until it ends; the token server's errors map to `BadKey`, `BadRequest`, `RateLimited`, `Overloaded` and `TimedOut` as listed; tokens are fetched one at a time across the program; the JWT is made with the machine's clock, with no correction for skew.
- Costs use each model's standard price (8.4, *Prices*), for a maintainer's review: a setting passed through a `Model`'s `extra` that changes Anthropic's price isn't seen, so the estimate is off: fast mode (Opus 5.5 $8/$40, Fable 5.2 $16/$80 per million tokens), US-only inference (`inference_geo: "us"`, 1.1 times) and the Batch API (half price).
