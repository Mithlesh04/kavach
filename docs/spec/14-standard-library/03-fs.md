# 14.3 std.fs

Paths are text, relative to the folder the program runs in.

| Function | Gives |
|---|---|
| `fs.read_text(path) -> String ! FsError` | The file's text (it must be UTF-8) |
| `fs.write_text(path, text) ! FsError` | Replaces the file **atomically**: the new text goes to a temporary file that is then renamed, so a crash never leaves half a file |
| `fs.append_text(path, text) ! FsError` | Adds to the end, creating the file if needed |
| `fs.read_bytes(path) -> Bytes ! FsError` | The file's contents, any bytes (2.13) |
| `fs.write_bytes(path, data) ! FsError` | Replaces the file atomically, like `write_text` |
| `fs.write_durable(path, data) ! FsError` | Replaces the file atomically **and forces it to the disk** (`fsync` on the file, then on its folder) before returning: after it, a power cut keeps the new contents. Storage engines build on this |
| `fs.lines(path) ! FsError` | The file's lines, read as a `for` loop goes, without their line ending (`\n` or `\r\n`) |
| `fs.chunks(path, size) ! FsError` | The file's bytes in `Bytes` pieces of `size` (the last may be shorter), read as a `for` loop goes |
| `fs.exists(path) -> Bool` | Whether a file or folder is there |
| `fs.list(folder) -> [String] ! FsError` | The names in a folder, sorted |
| `fs.remove(path) ! FsError` | Deletes a file or an empty folder |
| `fs.create_dir(path) ! FsError` | Creates a folder and any missing parents |
| `fs.info(path) -> FileInfo ! FsError` | What is at `path`: its kind, size, last change and permissions (below). A link is described itself, not what it points to |
| `fs.set_read_only(path, read_only) ! FsError` | Makes a file read-only, or writable again, on every system |
| `fs.set_permissions(path, mode) ! FsError` | Sets the Unix permission bits, written in octal: `0o644`, `0o755`. Windows keeps only whether the owner may write: without that bit the file is read-only |
| `fs.rename(from, to) ! FsError` | Moves or renames a file or folder; a file already at `to` is replaced |
| `fs.copy(from, to) ! FsError` | Copies a file, with its permissions; a file already at `to` is replaced |
| `fs.remove_all(path) ! FsError` | Deletes a folder and everything in it, or a file |
| `fs.symlink(target, link) ! FsError` | Makes a symbolic link at `link` that points to `target`, kept as written (a relative `target` is relative to the link's folder). With `uses Fs("…")` (8.1) both must be inside its folders. Windows allows it only in Developer Mode or with administrator rights; otherwise it fails with `Denied` |

`fs.lines` gives a reader of type `Lines` and `fs.chunks` one of type `Chunks`, which a variable or a field can hold, as a streamed HTTP response does (14.11). They keep memory small for a file of any size: only the part being looked at is in memory, and for pieces of 1 MB or more the next piece too: a native program reads it while the loop works on this one, so the disk and the work overlap. The file's bytes and the order of the pieces stay the same, and an error comes at the same point of the loop; a change the program makes to the file during the loop may not show in the piece after. They fail with an `FsError` when the file can't be opened. A file that can't be read further, or a line that isn't UTF-8 (`Failed(path, "not UTF-8")`), fails the same way, during the loop: the error goes to the `try` or `catch` in the loop's header, as an error opening the file does.

- With `try`, the function returns the error, so a half-read file is never mistaken for a whole one.
- With `catch`, the handler runs with the error, then the loop ends. A `return` in the handler returns from the function.
- A reader kept in a variable and looped over later has no header to send the error to: a failed read is then a panic.

```kavach
let errors = 0
for line in try fs.lines("server.log") {
    if line.contains("ERROR") {
        errors += 1
    }
}
```

### File details and permissions

`fs.info` gives a `FileInfo`:

```kavach
pub type FileKind = File | Folder | Link

pub type FileInfo {
    pub kind: FileKind
    pub size: Int          // in bytes; 0 for a folder
    pub modified_ms: Int   // when it last changed: a moment (14.4)
    pub read_only: Bool    // the owner may not write it
    pub permissions: Int   // the Unix bits, such as 0o644
}
```

```kavach
use std.fs

fn main() ! FsError uses Fs, Console {
    try fs.write_text("deploy.sh", "echo hi\n")
    try fs.set_permissions("deploy.sh", 0o755)    // anyone may run it, only the owner may change it
    const info = try fs.info("deploy.sh")
    print("{info.size} bytes, mode {info.permissions}")
    try fs.set_read_only("deploy.sh", true)
}
```

- **On Windows,** files have no Unix bits. `permissions` is `0o444` for a read-only file and `0o666` otherwise (`0o555` and `0o777` for a folder), as Go and Rust report them. `set_permissions` keeps only the owner's write bit (`0o200`): `0o444` makes a file read-only, `0o644` writable. A drive that keeps no Unix bits, such as a Windows drive mounted in Linux, keeps only read-only too.
- A `mode` outside `0o0` to `0o7777` fails with `Failed(path, "permissions are 0o0 to 0o7777")`.
- `fs.info` and `fs.exists` read, so they need `Fs.read`; the others change files and need `Fs.write` (8.1). A `uses Fs("folder")` must cover both paths of `rename` and `copy`.

A failed file operation returns an `FsError`:

```kavach
pub type FsError = NotFound(path: String) | Denied(path: String) | Failed(path: String, reason: String)
```

```kavach
use std.fs

const config = fs.read_text("app.toml") catch e => match e {
    fs.NotFound(_) => ""                       // no file yet: use the defaults
    _ => panic("can't read app.toml")
}
```

### Writing a file piece by piece

`fs.create_writer(path)` gives a `FileWriter`, which writes a file as its data comes: a large upload or an export is never held in memory whole.

```kavach
fn save(pieces: [Bytes], path: String) -> Int ! FsError uses Fs.write {
    const w = try fs.create_writer("{path}.part")
    for piece in pieces {
        try w.write(piece)
    }
    const size = try w.finish(sync: true)
    try fs.rename("{path}.part", path)
    size
}
```

| Function or method | Gives |
|---|---|
| `fs.create_writer(path) -> FileWriter ! FsError` | A new, empty file at `path` to write; one already there is emptied |
| `w.write(data) ! FsError` | Adds the `Bytes` `data` at the file's end. Writes are gathered in memory and go to the file 64 KB at a time |
| `w.write_text(text) ! FsError` | The same for text, as UTF-8 |
| `w.finish(sync: false) -> Int ! FsError` | Writes what is gathered, closes the file, and gives how many bytes it holds. With `sync: true` it also forces them to the disk (`fsync`), so a rename after it can't leave a short file after a crash |

- A writer let go before `finish` closes its file and deletes it, so an upload cut short leaves nothing behind.
- After `finish`, `write` fails with `Failed(path, "finished")`, and `finish` gives the same count again.
- Unlike `write_bytes`, the file is written in place, not replaced at once: other programs can see it grow. Write to another name and `fs.rename` it, as above, when that matters.
- It needs `Fs.write` (8.1), and with `uses Fs("…")` the path must be inside its folders, as every file operation's.
