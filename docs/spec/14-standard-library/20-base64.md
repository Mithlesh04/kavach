# 14.20 std.base64

Bytes written as text and read back, as RFC 4648 says, in the standard alphabet (`+` and `/`) or the URL-safe one (`-` and `_`). Sign-in protocols, tokens, cookies and email all need it. It is built into the runtime and needs no capability: it changes nothing outside the program (8.1).

| Function | Gives |
|---|---|
| `base64.encode(data, url: false, pad: true) -> String` | `data` (`Bytes`) as base64 text: URL-safe when `url`, with `=` padding when `pad` |
| `base64.decode(text, url: false) -> Bytes ! Base64Error` | The bytes `text` encodes, in the alphabet `url` picks |

Decoding is strict, so one value has one text, which signed tokens rely on. Padding may be left out, but when it is there it must be right. The errors:

| `Base64Error` | When |
|---|---|
| `BadCharacter(at: Int)` | A character outside the alphabet, at this character index |
| `BadLength` | A length no encoding gives |
| `BadPadding` | `=` where it doesn't belong, or the wrong number of them |
| `ExtraBits` | Bits after the last byte that aren't zero |

```kavach
use std.base64

const token = base64.encode(signature, url: true, pad: false)     // for a JWT
const data = try base64.decode(header_value)
const sealed = base64.decode(cookie, url: true) catch e => match e {
    Base64Error.BadCharacter(at) => fail Unauthorized(reason: "a bad character at {at}"),
    _ => fail Unauthorized(reason: "not base64"),
}
```
