What Is Tested: GPU

● Intermediate5 min

The conformance tests of spec chapter 15, GPU, by section.

54 tests: 15 check that it works, 39 that wrong use is refused.

15.1 gpu fn

RuleSpecChecksTest
A gpu fn calls only other gpu fns: calling a plain fn of the same types is a compile error.15.1refused: compile errorgpu-fn-calls-no-plain-fn
A gpu fn calls only other gpu fns, conversions, and abs, min, max, clamp.15.1refused: compile errorgpu-fn-calls-only-gpu-fns
A gpu fn may convert between Float32, Int32 and UInt32, and use abs, min, max and clamp.15.1, 2.1worksgpu-fn-converts-and-clamps
A gpu fn gives only Float32, Int32, UInt32 and Bool, or records and tuples of them.15.1refused: compile errorgpu-fn-gives-only-32-bit-types
A gpu fn can't fail: ! in its signature is a compile error.15.1refused: compile errorgpu-fn-has-no-error-type
A gpu fn gives its result back; it can't take inout parameters.15.1refused: compile errorgpu-fn-has-no-inout
A gpu fn's body uses only the statements 15.1 lists (if and else, while, for over a range, return, …): match is not one.15.1refused: compile errorgpu-fn-has-no-match
A gpu fn can't reach itself through calls: a GPU has no call stack.15.1refused: compile errorgpu-fn-has-no-recursion
A gpu fn's const and let hold only the 32-bit types and Bool.15.1refused: compile errorgpu-fn-locals-are-32-bit
A gpu fn uses no lists, in its body as in its signature.15.1refused: compile errorgpu-fn-makes-no-lists
A gpu fn, or a lambda calling one, maps a list; in a gpu fn, literals are 32-bit.15.1, 15.2worksgpu-fn-maps-a-list
In a gpu fn, ** works on Float32 only; on whole numbers it is a compile error.15.1refused: compile errorgpu-fn-power-is-float32-only
The records a gpu fn takes have fields only of Float32, Int32, UInt32 and Bool.15.1refused: compile errorgpu-fn-record-fields-are-32-bit
A record a gpu fn takes or gives has 1 to 8 fields.15.1refused: compile errorgpu-fn-records-have-at-most-8-fields
A gpu fn takes and gives only Float32, Int32, UInt32 and Bool, and records and tuples of them.15.1refused: compile errorgpu-fn-takes-32-bit-types
A gpu fn takes and gives records and tuples of 1 to 8 fields of the four types, reading their fields and making new ones.15.1worksgpu-fn-takes-and-gives-records
A gpu fn may use math.sin, cos, tan, asin, acos, atan, atan2, exp and ln on Float32; they give a Float32.15.1, 14.5worksgpu-fn-uses-angles-exp-and-ln
A gpu fn may use math.sqrt, floor, ceil, round and pow on Float32; they give a Float32.15.1, 14.5worksgpu-fn-uses-math
A gpu fn can't use capabilities: reading a file in one is a compile error that says so.15.1refused: compile errorgpu-fn-uses-no-capabilities
A gpu fn uses no maps.15.1refused: compile errorgpu-fn-uses-no-maps
A gpu fn uses no text.15.1refused: compile errorgpu-fn-uses-no-text
A gpu fn may use let, assignment, if and else, while, for over a range and return.15.1worksgpu-fn-uses-while-if-and-return
A map gives what calling its gpu fn on each item directly gives: the code and the results are the same wherever it runs.15.1, 15.2worksgpu-results-match-direct-calls

15.2 Running on the GPU

RuleSpecChecksTest
A panic in the second of two chained maps stops the work with that map's message, as on the CPU.15.2refused: panicgpu-chained-map-panic-gives-its-message
maps chained in one expression give the results of each map in turn, on the GPU as on the CPU, with each lambda's captured values.15.2worksgpu-chained-maps-run-as-one
Whole-number division by zero in a gpu fn that a map runs panics, as it does on the CPU.15.2, 5.6refused: panicgpu-division-by-zero-panics
filter of a list a GPU map made keeps the items the CPU keeps, in their order, and can be mapped and summed after it.15.2worksgpu-filter-keeps-the-order
A GPU map whose lambda reads a field of a captured record runs on the CPU, and the compiler warns, naming the field; the results are the same.15.2refused: warninggpu-map-reading-a-captured-field-warns
A list a GPU map made is an ordinary list: changing a second holder of it copies it first.15.2, 2.2worksgpu-mapped-list-changes-by-copy
A loop of maps feeding each result to the next gives, at the first read after the loop, every item as the CPU works it out.15.2worksgpu-maps-in-a-loop-are-read-after-it
A lambda calling gpu fns maps a list of records or tuples of the four types, reading their fields.15.2worksgpu-maps-records-and-tuples
Whole-number overflow in a gpu fn panics, as it does on the CPU.15.2, 5.6refused: panicgpu-overflow-panics
sum, min and max of Int32 or UInt32 give the CPU's answers wherever they run, and a sum that overflows panics as the CPU adds it.15.2refused: panicgpu-sum-min-max-of-whole-numbers
a loop's sums the loop doesn't wait for are added in order, each with its checks, before any code after the loop.15.2refused: panicgpu-sums-in-a-loop-run-in-order

A gpu vertex fn follows the rules of a gpu fn: it can't print.15.3, 15.1refused: compile errorgpu-vertex-fn-follows-gpu-fn-rules
